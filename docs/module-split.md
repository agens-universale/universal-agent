# Разбиение на модули: `gc_core` / `gc_cli` / `gc_tui` / `gc_server`

Статус: переезд выполнен, тесты разнесены по пакетам; ветка `feat/module-split`
База: 0.4.0 (`feat/install-extras`) — профили уже разделены на дистрибутивы

## Цель

Превратить ядро в **SDK**: пакет с собственным пространством имён, который можно
импортировать из чужого приложения, не конфликтуя с его модулями. Фронтенды
(`cli`, `tui`, `server`) — отдельные пакеты-потребители этого SDK.

Это **не** про раздельную установку файлов: она сделана в 0.4.0 четырьмя
манифестами над общим `src/`, без единой правки импортов, и переездом не
отменяется.

## Зачем

Ядро занимает **45 имён верхнего уровня** в `site-packages`:

```
config  tools  utils  states  security  instructions  constants  backends
persistence  summarize  updater  usage  onboarding  model_picker  app_version
```

Любое приложение со своим `config.py` или пакетом `utils/` конфликтует с
агентом. Namespace-префикс — единственное, что это лечит.

Прочие мотивы отпадают, зафиксировано, чтобы к ним не возвращаться:

| Мотив | Статус |
|---|---|
| Раздельная установка файлов | сделано в 0.4.0 без переезда |
| Размер установки | дают разные зависимости профилей |
| Принудительная граница | даёт разделение дистрибутивов |
| Независимые релизные циклы | даёт разделение дистрибутивов |

## Целевая раскладка

```
universal-agent/
  pyproject.toml                 # мета gc-ua + корень uv-workspace
  meta/gc_ua_launcher.py
  packages/core/
    pyproject.toml               # дистрибутив gc-core — БЕЗ [project.scripts]
    src/gc_core/                 # 277 модулей SDK
    assets/                      # prompts/, skills/, config.default.yml, recommended_mcp/
  packages/cli/
    pyproject.toml               # gc-cli   → gc-core
    src/gc_cli/                  # cli.py, arg_parser.py, onboarding_wizard.py
  packages/tui/
    pyproject.toml               # gc-tui   → gc-core
    src/gc_tui/                  # бывшие tui/ и diff_tui/
  packages/server/
    pyproject.toml               # gc-server → gc-core
    src/gc_server/               # server.py, rest_api/, swarm/
  packages/testkit/
    pyproject.toml               # gc-testkit — только dev, в колёса не попадает
    src/gc_testkit/              # раскладка, фикстуры, pytest-плагин
  tests/                         # только общерепозиторное: колёса, MCP, litellm
```

Наборы тестов лежат в `packages/*/tests` — по одному на дистрибутив.

Каталог называется `packages/`, а не `packaging/`: там теперь лежит код, а не
только манифесты. Хвост в командах установки меняется соответственно —
`#subdirectory=packages/tui`.

### Дистрибутивы

| Дистрибутив | Пакеты | Зависит от | Команды |
|---|---|---|---|
| `gc-core` | `gc_core` | — | **нет** |
| `gc-cli` | `gc_cli` | `gc-core` | `gc-cli` + mcp |
| `gc-tui` | `gc_tui` | `gc-core` | `gc-ua` + mcp |
| `gc-server` | `gc_server` | `gc-core` | `gc-serve` + mcp |
| `gc-ua` (мета) | — | все три | все пять |

`gc-core` — библиотека, поэтому **не объявляет точек входа** и ставится иначе:

```bash
uv pip install "gc-core @ git+URL#subdirectory=packages/core"   # в своё приложение
uv tool install "gc-cli @ git+URL#subdirectory=packages/cli"    # как инструмент
```

Фронтенды друг от друга не зависят: проверено — `cli`, `arg_parser` и
`onboarding_wizard` не импортирует никто, кроме самих себя.

### Границы, посчитанные по графу импортов

| Пакет | Модулей | Пакетов верхнего уровня |
|---|---|---|
| `gc_core` | 277 | 45 |
| `gc_cli` | 3 | `cli`, `arg_parser`, `onboarding_wizard` |
| `gc_tui` | 112 | `tui`, `diff_tui` |
| `gc_server` | 12 | `server`, `server_cleanup_threads`, `rest_api`, `swarm` |

### Осознанный долг: оболочка приложения в SDK

Одиннадцать пакетов нужны cli и tui, но не нужны server:

```
onboarding, onboarding_config_writer, onboarding_fields, updater, upgrade_gate,
app_version, config_sync, config_raw, config_origin, model_picker,
mcp_daemon_autostart
```

Это мастер первого запуска, самообновление и редактирование конфига — не логика
агента. **Решено класть их в `gc_core`** (2026-08-17), чтобы не плодить пятый
пакет. Цена: SDK носит механизм самообновления через `uv tool install`, который
встраивающему не нужен.

Туда же по необходимости попадают шимы `tui_entry.py` и `serve_entry.py`:
охранники команд `gc-ua`/`gc-serve` обязаны быть доступны в профиле `gc-cli`, а
единственное общее у всех профилей — ядро.

Если долг начнёт мешать, выделяется пакет `gc_app` — граница уже посчитана и
проходит ровно по этим одиннадцати пакетам плюс два шима.

### Ассеты

В репозитории ассеты лежат в `packages/core/assets/`, в колесе — внутри пакета,
в `gc_core/assets/`. `bundled_root()` знает обе раскладки и считает путь от
своего `__file__`.

Внутрь пакета они переехали 18.08.2026, вторым заходом. Первый (переезд из корня
репозитория в `packages/core/assets/`) чинил только рабочую копию: в колесе
ассеты по-прежнему распаковывались РЯДОМ с пакетом, прямо в `site-packages`, и
дистрибутив занимал там родовые имена `prompts`, `skills`, `external`,
`recommended_mcp`. Проверено в чистом venv: `import prompts` у встраивающего
резолвился в наши промпты. То есть заявленная цель «одно имя вместо 45» была
достигнута лишь наполовину — стало четыре. Сейчас два, и оставшиеся два уносит
задача про вынос MCP.

Промпт TUI и `server_agent.md` остаются в ассетах ядра: `bundled_root()`
резолвится от `__file__` ядра, и фронтенды дотягиваются оттуда — проверено на
установленном профиле 0.4.0.

Следствие: встраивающий получает вместе с SDK ~400 КБ промптов и скиллов. Это
правильно — без системного промпта агент не работает.

| Что | Объём |
|---|---|

### 354 динамических места — главный риск

Первый греп по `importlib.import_module|__import__|sys.modules[` дал 84. Это
занижение вчетверо: AST-скан строковых литералов в позициях динамического
резолва даёт 354.

```
monkeypatch.setattr("mod.attr")         153
mock.patch("mod.attr")                   82
sys.modules[...] (все формы)             53
startswith("mod.") — фильтры выселения   34
types.ModuleType("mod")                  22
importlib.import_module                  17
f-строки  f"mod.{x}"                      4
имена логгеров  assertLogs("mod.x")       2
uvicorn.run("mod:app")                    1
```

Цифры — фактические, из `gc_testkit.module_literals` после переезда
(гоняется тестом `tests/test_module_literals.py`).

По целям: `tools` 112, `summarize` 86, `tui` 24, `config` 19,
`processing_responses` 13, `utils` 12.

Делятся на два класса, и второй определяет весь план:

- **Громкие** (234): `monkeypatch.setattr` / `mock.patch`. Устаревшая строка →
  `ModuleNotFoundError` / `AttributeError`, тест краснеет.
- **Тихие** (~110): записи в `sys.modules`, `types.ModuleType`, фильтры
  `startswith("tools.")`. Устаревшая строка ошибки не даёт — цикл выселения
  становится пустым, заглушки протекают между тестовыми файлами, набор
  остаётся зелёным.

**Следствие: зелёный набор после переезда ничего не доказывает.** Самый плотный
узел — `tests/tools/conftest.py` и `tests/security/conftest.py`: они ставят
фальшивый пакет `tools` со вложенными `tools.fs` / `tools.exec`, а затем
выселяют его по префиксу.

### В `src/` динамики почти нет

Из 404 модулей `src/` динамических резолвов ровно два:

- `src/tui/__init__.py:50` — `importlib.import_module("tui.app")`;
- `src/server.py:762` — `uvicorn.run("server:app", …)`.

Второй уже ломался дважды по этой же причине (было `"src.server:app"`, чинили
при переходе на `sources = ["src"]`).

Первый опаснее: он в `except ImportError` и печатает подсказку про отсутствующий
профиль. `ModuleNotFoundError` — подкласс `ImportError`, поэтому устаревшее имя
покажется пользователю как «не установлен textual», и совет переустановиться не
поможет.

## План

Порядок обязателен, каждый шаг проверяется отдельно.

1. **Сетка защиты от тихих поломок.** До единой правки импортов — проверка,
   сверяющая все 354 строковых литерала с существующими модулями и атрибутами.
   Без неё зелёный набор ничего не значит. Пропускать нельзя.
2. **Кодмод по AST.** Переписывает 5077 импорт-узлов, не трогая строки и
   комментарии. Прототип проверен на копии `src/`: 268 файлов, 1280 узлов, ноль
   синтаксических ошибок, ноль предупреждений — смешанных и точечных импортов в
   проекте нет.
3. **Два динамических места в `src/`** — руками.
4. **354 строковых места** — кодмодом, с обязательной проверкой шага 1.
5. **Физический переезд** через `git mv` (история сохраняется).
6. **Манифесты** — перечни `force-include` заменяются на `packages`.
7. **Ассеты** — переезд в `packages/core/assets/` + правка резолвера.
8. **Пути в тестах** — 41 файл строит путь к `src/`; ввести `tests/paths.py` и
   заменить обращения через него.
9. **Проверка установки** всех пяти дистрибутивов из git-URL.
10. **Разделение тестов** по пакетам — сделано. Правило: файл принадлежит самому
    «верхнему» пакету из тех, что импортирует (фронтенд важнее ядра, потому что
    зависит от него). Итог: 412 файлов ядру, 318 TUI, 17 cli, 11 server;
    23 общерепозиторных остались в корне. Подробности — в `docs/testing.md`.

    Смысл шага не в опрятности: пока тесты общие, утверждение «ядро
    самодостаточно» не проверяется ничем. Теперь проверяется —
    `cd packages/core && pytest` даёт 3252 passed без единого фронтенда.

    Два побочных результата, ради которых шаг и стоил своей цены:

    - Тест `test_memory_cutover_invariants` сканировал `<repo>/src`. После
      переезда на пакеты каталог исчез, `rglob` стал возвращать пустоту — и
      проверка **молча проходила на любом коде**. Переезд её оживил; добавлена
      страховка `test_scan_actually_covers_sources`, падающая на пустом обходе.
    - Полтора десятка тестов считали корень репозитория как
      `Path(__file__).resolve().parents[N]`, а один — от `cwd`. Все переведены
      на `gc_testkit.paths.REPO`; мёртвые вычисления сняты.

Компат-шимы (модули под старыми именами) — **нет**: они вернут пересечение
путей между колёсами и разрушат инвариант, на котором держится 0.4.0.

## Открытые вопросы

1. **Публичная поверхность `gc_core`.** Сейчас у ядра нет `__all__` и нет
   границы между «можно импортировать» и «внутреннее». Без этого переезд даёт
   красивые имена, но не даёт контракта — а ради контракта всё и затевается.
2. ~~**Тесты.**~~ Закрыто: наборы разнесены по пакетам, общая инфраструктура
   вынесена в dev-дистрибутив `gc-testkit` (пакет `gc_testkit`), корневой
   `tests/conftest.py` стал его pytest-плагином. См. `docs/testing.md`.
