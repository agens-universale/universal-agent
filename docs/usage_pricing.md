# Подсчёт токенов и стоимости прогона

gc-cli считает токены, потраченные за прогон агента, по всем вызовам LLM, и показывает
стоимость. Цена берётся из ответа провайдера, если он её сообщает (так делают OpenRouter
и routerai.ru); иначе считается по тарифу из `config.yml`. Кумулятив сохраняется в метаданных треда и
восстанавливается при продолжении (`-t`).

## Что считается

Учитываются **все** обращения к модели, с разбивкой по категориям:

| Категория | Какие вызовы |
|---|---|
| `main` | основной агент (вызовы модели в цикле, включая отброшенные при переигрыше ответы) |
| `finish_gate` | LLM-судья качества (валидация `turn_finish`) |
| `routing_judge` | судья сложности для выбора начальной пары AUTO; при двух моделях не вызывается |
| `summary` | суммаризация / компакция контекста |
| `command_moderation` | judge опасных команд (`exec_command`/`exec_python`) |
| `project_memory` | компакция project-памяти |
| `intent_scope` | post-hook intent-scope |
| `vision` | «глаза»: описание изображения моделью для зрения (`assign.vision`) |
| `subagent` | свёрнутый вклад субагентов (их main + aux) |

Для каждой категории хранятся `input` / `output` / `cached` токены, число вызовов (`calls`) и
число вызовов без usage (`missing_usage_calls`). Дополнительно — подмножество вызовов, для
которых известна **фактическая** цена: `billed_calls` и их токены `billed_input` /
`billed_output` / `billed_cached`, плюс сами суммы `cost_by_currency` — словарь
«валюта → сумма» (см. [ниже](#откуда-берётся-цена)):

```json
"main": {
  "input": 840000, "output": 40000, "calls": 3,
  "billed_calls": 3, "billed_input": 800000, "billed_output": 40000,
  "cost_by_currency": {"$": 2.0, "₽": 200.0}
}
```

Суммы разных валют не складываются: курсов мы не знаем, а провайдер мог смениться посреди
треда. Ключ `""` означает «валюта не записана» — так читаются `meta` от версий, где сумма
была голым числом `cost` (миграция не нужна, такие суммы разрешаются при показе по текущему
адресу эндпоинта, ровно как вела себя прежняя версия).

**Токены считаются всегда**, независимо от того, задан тариф или нет.

## Откуда берётся цена

Для каждой категории источник выбирается автоматически:

| Состояние категории | Цена | Валюта |
|---|---|---|
| все вызовы вернули стоимость | факт провайдера | по адресу вызова: `.ru` → `₽`, иначе `$` |
| ни один не вернул, тариф задан | расчёт по тарифу | `pricing.currency` |
| ни один не вернул, тарифа нет | цены нет — только токены | — |
| часть вернула, тариф задан | факт + тариф на остаток токенов | обе |
| часть вернула, тарифа нет | факт; остаток остаётся без цены | по адресу вызова |

Фактическую стоимость присылают **OpenRouter** и **routerai.ru** — в поле `usage.cost` каждого
ответа, без дополнительных флагов, в том числе в стриминге. Механизм провайдер-агностичный:
любой эндпоинт с тем же полем подхватится сам. Cloud.ru, GigaCode (через LiteLLM-прокси) и
локальный vLLM цену не сообщают — для них работает тариф. Всё перечисленное проверено живыми
вызовами, а не документацией провайдеров.

Цена провайдера приходит **с каждым вызовом отдельно**, поэтому учитывает смену моделей,
ролей и провайдера под одним именем модели. Тарифный расчёт также разделяет расход по
фактическим моделям вызовов: для каждой берётся её ставка из `pricing.models` либо явно
заданный общий тариф. Смену провайдера под тем же именем модели тариф сам не определяет;
ставки нужно поддерживать в конфиге. Вызовы с фактической ценой повторно по тарифу не считаются.

Ограничения:

- `cost` не сообщает валюту, поэтому она **выводится из адреса вызова**: домен `.ru` —
  рубли, всё остальное — доллары. Валюта определяется в момент записи вызова и хранится
  вместе с суммой, поэтому смена провайдера посреди треда не переразмечает уже
  накопленные деньги, а при `assign` в профилях каждая роль получает валюту своего
  эндпоинта. Настройки для этого нет намеренно: цена должна показываться сама, без похода
  в конфиг. Основание — замеры: OpenRouter биллит в долларах, routerai.ru — в
  рублях (его прайс сошёлся с долларовыми ставками тех же моделей по курсу ~107.9
  на двух моделях и обеих ставках). Правило ошибётся в обе стороны: не-российский
  биллинг на `.ru`-домене разметится рублями, а российский провайдер на `.com`,
  `.su` или `.рф` — долларами (`.рф` в punycode правилом не распознаётся).
  Среди проверенных провайдеров таких нет; когда появится — исключение заводится
  одной строкой в `usage/currency.py`. Ошибка задевает только символ рядом с числом:
  сама сумма приходит от провайдера и не искажается;
- при `is_byok: true` (запрос через ваш собственный ключ провайдера) факт **не используется** —
  неизвестно, содержит ли `cost` полную цену или только комиссию; такой вызов идёт в тариф,
  если тариф задан, иначе остаётся без цены вовсе (маркер `?`);
- `cost: 0` у бесплатной модели — это факт «бесплатно», а не «цена неизвестна».

## Вывод

В конце прогона при `logging.console_trace: true` печатается таблица (и всегда пишется в лог).
Показывается usage **именно этого прогона** (дельта); кумулятив по треду живёт в meta.

```
Run usage    models: anthropic/claude-opus-5
category                 input    output                  cost
main                      1.2M     45.0k                6.15 $
subagent                847.0k     19.1k        4.30 $+~9.16 ₽
finish_gate              88.6k       319               ~5.27 ₽
──────────────────────────────────────────────────────────────
total                     2.1M     64.4k                     —
subtotals by currency:
  10.5 $ (факт провайдера)
  14.4 ₽ (расчёт по тарифу)
~ — расчёт по тарифу
```

Заголовок называет модели, в которые реально ушли вызовы прогона, — по телу запроса, а не
по верхнему полю `model` конфига (при реестре `models`/`slots` оно для вызовов не читается).
Если моделей больше одной (автовыбор уровня, субагенты на своей модели), под итогом идёт
раздел `by model:` — токены каждой модели, в порядке первого вызова:

```
Run usage    models: Qwen3.6-35B, dsv4flash-ctx327k-bb
category                 input    output
main                      1.6M     13.7k
finish_gate              39.1k        68
command_moderation       28.1k       891
────────────────────────────────────────
total                     1.7M     14.7k
by model:
Qwen3.6-35B             540.1k      6.7k
dsv4flash-ctx327k-bb      1.2M      8.0k
```

Деньги в разделе по моделям не показываются — они ведутся по категориям.

Маркеры — одни и те же в CLI-отчёте, в футере TUI и в `/sessions`:

- `+` — **соединитель слагаемых**, а не признак проблемы: `4.30 $+~9.16 ₽` читается как
  «четыре доллара тридцать и ещё девять рублей шестнадцать». Разные валюты не складываются,
  поэтому показываются рядом;
- `~` — эта часть суммы посчитана по тарифу, а не измерена провайдером. Ставится, только
  если в отчёте есть **обе** стороны — и факт, и тариф (как выше: `main`/`subagent` дают
  факт, `subagent`/`finish_gate` — тариф). Если весь прогон посчитан одним способом —
  целиком по факту или целиком по тарифу — тильды нет нигде: ни в ячейках, ни в
  подытогах, ни в футере TUI, ни в `/sessions`, легенда `~ — расчёт по тарифу` не печатается;
- `?` — есть вызовы, стоимость которых показать неоткуда: провайдер цену не сообщил и
  тарифа нет (легенда `? — часть вызовов без цены, итог неполный`).
  Может сочетаться с тарифной суммой: известные модели оценены, оставшаяся часть — нет;
- `—` в `total` — в прогоне больше одной валюты, единого итога нет (курсов мы не знаем),
  сабтоталы печатаются ниже; категория совсем без цены (нет ни факта, ни тарифа) в своей
  ячейке — тоже `—`, без `?`: неполнота итога видна на строке `total` и в легенде, а не
  в каждой пустой ячейке.

Формат чисел: деньги — два знака после запятой для сумм меньше 10 и один знак от 10 и выше
(порог применяется к округлённому значению); ненулевая сумма, которая округляется в ноль,
печатается как `<0.01` — «меньше минимальной денежной единицы», а не «бесплатно».
Токены — 1 знак при сокращении
`k`/`M`. Колонка `cost` появляется, когда есть хоть какая-то цена — фактическая или расчётная.
Если ставки заданы, но ничего из потраченного в сессии оценить не удалось, колонка и
значок `?` всё равно показываются — сессия не выглядит бесплатной. Ставок нет совсем —
стоимость остаётся скрытой. При `pricing.enabled: false` денег не показывается вовсе,
остаются одни токены.

Метка подытога (`факт провайдера` / `расчёт по тарифу` / `факт + расчёт`) выбирается по
фактическим источникам частей, попавших в эту валюту, а не по самой валюте — если тариф
для какой-то модели тоже задан в долларах, долларовый подытог может оказаться смешанным.

В TUI те же данные живут в правой части футера: `запрос <токены>/<цена> · сессия <токены>/<цена>`,
с теми же маркерами — например `сессия 840.0k/2.00$+200.0₽~`. Показываются **все** валюты:
доля токенов не пропорциональна деньгам, поэтому свернуть картину до одной цифры значило бы
спрятать неизвестно какую часть суммы — основной могла оказаться как раз спрятанная.
Каждый сегмент показывает свои валюты: у «запроса» их обычно меньше, чем у «сессии».
Порядок валют детерминирован — первой идёт валюта категории с наибольшими токенами, иначе
футер прыгал бы между перерисовками. Расшифровка маркеров есть в справке (F1), блок
«токены и стоимость». В `/sessions` формат тот же, с пробелом перед валютой.

Отдельный приятный случай: если эндпоинт на `.ru` и ставки в конфиге тоже рублёвые,
факт и тариф оказываются в одной валюте и складываются в одну сумму — второго слагаемого
не появляется, а с ним и соединителя `+`.

Валюта сумм из **старых** сессий (записанных до того, как валюта стала фиксироваться на
вызове) считается по текущему конфигу: адрес эндпоинта в тех `meta` не сохранён.
Новые суммы этому ограничению не подвержены: их валюта записана рядом с числом.

## jsonl-событие `run_usage`

Помимо текстовой таблицы, в конце прогона в jsonl-лог треда пишется структурный
эквивалент того же отчёта — событие `run_usage`. У каждой категории:

- `input` / `output` / `cached` / `missing_usage_calls` — те же токены, что и в таблице;
- `cost_source` — откуда взята цена категории: `provider` (целиком факт), `tariff`
  (целиком расчёт), `mixed` (и то и другое) или `none` (цены нет вовсе — нет ни факта,
  ни тарифа; попадает в `unpriced`, категория просто не участвует в `cost`);
- `cost_parts` — список слагаемых `{amount, currency, source}` (`source`: `provider` |
  `tariff`); для читаемости, если слагаемое одно, дублируется плоскими `cost` / `currency`;
- `unpriced` — `true`, если у категории есть токены, цену которых узнать нечем.

На уровне всего отчёта: `cost.by_currency` — суммы по валютам (как сабтоталы в таблице);
`models` — расход по моделям вызова: `{"<модель>": {input, output, calls}}`, плюс `cached` /
`missing_usage_calls`, когда они не нулевые (денег здесь нет). Поле `model` — по-прежнему
верхнее значение конфига, оставлено для совместимости; какие модели работали, говорит `models`.
Вклад субагентов входит в `models` под их собственными моделями (в категориях он свёрнут в
`subagent`).
Легенды в jsonl нет — маркеры `+`/`~`/`?` это только текстовое представление; в jsonl та же
информация читается напрямую из `cost_parts`/`cost_source`/`unpriced`.

## Конфигурация тарифа (`pricing`)

Секция `pricing` в `config.yml`. `enabled` — рубильник показа денег: при `false` цена не
показывается вообще, даже если провайдер её прислал (токены остаются).

Ставки нужны только провайдерам, которые не сообщают стоимость сами. На OpenRouter секцию
можно не заполнять — цена придёт от провайдера.

Для одно-модельного агента ставки задаются **на верхнем уровне** (имя модели указывать не нужно):

```yaml
pricing:
  enabled: true
  currency: "₽"
  per_tokens: 1000000          # ставки указаны за столько токенов
  input: 59                    # ДЕФОЛТНЫЙ тариф — для моделей без своего тарифа
  output: 118
  cache_read: 0.49             # опц.: цена за per_tokens кэшированных входящих
```

Если моделей несколько — добавьте `models` для переопределения под конкретные имена:

```yaml
pricing:
  enabled: true
  currency: "₽"
  per_tokens: 1000000
  input: 59                    # дефолт для моделей без записи в models
  output: 118
  cache_read: 0.49
  models:
    "some/usd-model":          # ключ = точное имя модели в теле запроса
      currency: "$"            # override валюты
      per_tokens: 1000         # override единицы (тариф за 1K)
      input: 0.05
      output: 0.15
```

Правила:

- `enabled` — **только глобально** (рубильник показа денег);
- `currency`, `per_tokens` — глобальные (переопределяются в записи модели);
- `input`, `output`, `cache_read` на **верхнем уровне** — дефолтный тариф для фактических моделей без записи в `pricing.models`;
- **нулевые ставки = «не задано»**: если `input` и `output` оба равны нулю, тарифа нет —
  показывать «0.0» значило бы выдать «цена неизвестна» за «бесплатно». Ноль в одной из двух
  ставок осмыслен и работает; `cache_read: 0` — валидная ставка «кэш бесплатен»;
- **резолв тарифа**: для каждого вызова сначала ищется его реальное имя модели в `pricing.models` (запись с обоими нулями считается
  незаданной и откатывается на верхний дефолт); не найден → верхний дефолт; нет ни там,
  ни там → тарифа нет (цена может прийти от провайдера, иначе показываются одни токены);
- запись модели без `cache_read` наследует верхнеуровневый `cache_read`;
- расчёт по тарифу: `(input − cached)·input_rate + cached·cache_read + output·output_rate`
  (если `cache_read` не задан — `cached` биллится по `input_rate`); при смешанной категории
  тариф применяется только к остатку — токенам, за которые не пришла фактическая цена;
- разные валюты за один прогон → сабтоталы по валютам, без единого total (без конвертации курсов).

Если `pricing.enabled: true`, а ставки не заданы ни для одной модели конфига, при старте
показывается ноутис `pricing_no_rates`: провайдеры с фактической ценой всё равно покажут
стоимость, остальные — нет. Если ставки есть не у всех моделей, показывается ноутис
`pricing_partial_rates` со списком моделей без ставки: их стоимость отмечается `?`.

## Кэш (prompt cache)

Многие провайдеры (DeepSeek и др.) тарифицируют повторяемый префикс запроса (system-промпт +
история диалога) по дешёвой cache-ставке. В агентском цикле это большая доля входа. gc-cli
извлекает кэшированные токены из ответа (`usage.prompt_tokens_details.cached_tokens` у
OpenAI-совместимых, `prompt_cache_hit_tokens` у DeepSeek-native) и применяет `cache_read`-ставку.

Если задать только `input`/`output` без `cache_read`, кэш биллится по `input` — оценка будет
завышенной для провайдеров с кэшем, но прогон не пострадает. Когда цена приходит от провайдера,
`cache_read` не нужен вовсе: скидка уже учтена в `usage.cost`.

Кэш включается на стороне провайдера: у части моделей он работает сам (DeepSeek, Gemini,
GLM), у Anthropic — только по явной разметке `cache_control`. В режиме `chat_completions`
агент в главном цикле ставит её сам моделям, в чьём id есть `claude`: метка на системном
сообщении (покрывает описания инструментов и промпт) и метка на последнем сообщении
пользователя или результата инструмента, которая сдвигается с каждым вызовом. TTL — пять
минут. Между ходами системный блок пишется в кэш заново, если изменился листинг проекта,
память проекта или дата — системный промпт перерисовывается на каждый ход; внутри хода он
читается из кэша. Служебные вызовы (судьи, суммаризация) не размечаются — у них нет
повторяющегося префикса. Проверено живой пробой на OpenRouter (полное попадание между
шагами) и на routerai (системный блок и точный повтор запроса). Ключ
`backend.claude_prompt_cache` включает или выключает разметку принудительно, в том числе на одну
модель. Если прокси отвергает разметку (400 на `cache_control`), выключите её ключом
`backend.claude_prompt_cache: false` — тогда собственное поле `cache_control` из
`chat_completion_kwargs` уходит как задано. Оговорка про тариф: токены, записанные в кэш,
Anthropic биллит по 1.25 от ставки `input`, а тарифный расчёт считает их как обычный ввод
— оценка занижена; фактическая цена от провайдера (`usage.cost`) точна.

## Где хранится (meta треда)

`token_usage` пишется в `meta_<system>_<thread_id>.json` (см. [Конфигурация](configuration.md))
**кумулятивно по треду** и восстанавливается при `-t`. Консольная таблица показывает дельту
текущего прогона; meta — накопленный итог.

В каждой категории рядом с токенами лежат `billed_calls` / `billed_input` / `billed_output` /
`billed_cached` и `cost_by_currency` — подмножество вызовов с фактической ценой и её суммы
по валютам. Внутри категории `by_model` сохраняет токены и биллённые подмножества каждой
модели; общая разбивка `by_model` продолжает показывать суммарные токены и вызовы моделей.
Тарифная часть считается отдельно для каждой модели: `input − billed_input` и так далее.

Старые meta продолжают читаться без миграции. Их фактические суммы сохраняются; остаток без
вложенной привязки к модели (старая meta, записанная до учёта по моделям, и вызовы без
модели) оценивается по тарифу текущей `agent.model`. Это именно оценка по нынешней ставке:
если модель агента с тех пор сменилась или используется реестр моделей (где `agent.model` не
обязательно та модель, что реально отработала), цифра может не совпасть с действительностью.
`?` ставится, только если у `agent.model` нет тарифа. Новые вызовы после восстановления
учитываются с детализацией и оцениваются независимо от старой части.

> Замечание: тариф применяется к токенам при рендере, поэтому правка ставок в конфиге меняет
> отображение уже накопленной сессии. Фактическая цена, наоборот, зафиксирована в момент
> вызова и от ставок не зависит. Если прогон выполнялся версией без учёта кэша (`cached`
> записан как 0), тарифная часть кумулятива переоценит стоимость на величину кэш-скидки.

## Поведение и гарантии

- Провайдер не вернул `usage` → вызов **не считается** (без оценки), инкрементится
  `missing_usage_calls`, в отчёте — пометка «итог — нижняя граница». Прогон не падает.
  Следствие для надёжности: `agent.session_token_limit` считает израсходованное по этим же
  данным, поэтому на таком провайдере бюджет остаётся нулевым и лимит **не срабатывает**.
  Ограничивать ран в этом случае нужно через `agent.max_tool_calls` / `agent.max_steps` —
  они от ответа провайдера не зависят. См. [configuration.md](configuration.md).
- Провайдер вернул `usage`, но без стоимости → токены учтены, цена берётся из тарифа;
  тарифа нет → категория помечается маркером `?` (итог неполный), сумма не выдумывается.
- Битое значение `cost` (не число, отрицательное) игнорируется — вызов идёт по тарифному пути.
- Субагенты в meta не пишутся (у них нет своего треда), но их usage и фактическая стоимость
  сворачиваются в категорию `subagent` родителя — каждая валюта отдельно, даже если субагент
  ходил на другой эндпоинт.
- Любой сбой в самом отчёте проглатывается (warning в лог) — учёт токенов не роняет прогон агента.
