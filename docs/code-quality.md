# Качество кода: pre-commit, ruff, complexipy, локальный Sonar

Гейт качества один и тот же у человека и у CI — `scripts/lint.sh`. Внутри него
pre-commit со всеми хуками из `.pre-commit-config.yaml`: гигиена файлов, ruff
(линт + формат), complexipy (когнитивная сложность) и
`scripts/sonar_like_check.py` — локальный аналог правил Sonar, которых нет ни
у кого другого.

Смысл затеи: замечание Sonar не должно быть новостью. Всё, что видит скан,
ловится на машине разработчика до коммита; что НЕ ловится — перечислено ниже
явным списком, а не умолчанием.

## Как поставить

```
uv sync --group lint
uv run --group lint pre-commit install     # или: uvx prek install
```

`prek` — совместимая реализация того же формата: быстрее и не требует Python.
Гонять им:

```
GC_LINT_RUNNER=prek scripts/lint.sh
```

## Как прогнать

```
scripts/lint.sh                       # весь репозиторий, как в CI
scripts/lint.sh packages/core/src     # только указанные пути
```

Отдельные инструменты, если нужно точечно:

```
uv run --group lint ruff check .                 # линтер
uv run --group lint ruff format .                # форматтер
uv run --group lint complexipy --quiet           # S3776, порог 15 + снимок
uv run python scripts/sonar_like_check.py packages/*/src packages/core/assets scripts integrations docs
```

## Область и строгость

`sonar.sources` в проектах организации — весь прод-код, тесты исключены
(`sonar.exclusions=**/tests/**`). Локальные проверки повторяют это деление.

| Что | Область | Строгость |
| --- | --- | --- |
| `ruff format`, `ruff check` | весь репозиторий, включая тесты и `scripts/` | ноль нарушений |
| complexipy (S3776) | `packages/*/src`, `packages/core/assets/skills/*/scripts`, `scripts/`, `integrations/` | core, cli, scripts, integrations — ноль; tui, server, mcp, testkit — снимок (см. ниже) |
| `sonar_like_check.py` | тот же прод-код плюс `docs/*.html` | ноль нарушений во всех модулях |

Не проверяется нигде: `external/`, `packages/*/external/` — вендорный код.
`packages/core/src/gc_core/tools/deprecated/` исключён из проверки сложности:
это мёртвый код, он ниоткуда не импортируется.

## Что выключено и почему

Полный список с обоснованиями — в `[tool.ruff.lint] ignore` корневого
`pyproject.toml`. Коротко:

* `E501` — длину строк держит форматтер;
* `RUF001`–`RUF003` — кириллица в строках и комментариях, это язык проекта
  (иначе ~27 тысяч ложных срабатываний);
* `UP006`, `UP007`, `UP035`, `UP045` — модернизация аннотаций `typing.*`:
  ~4 тысячи правок, отдельная задача;
* `B904`, `B905`, `B008`, `SIM105`, `SIM108`, `SIM117`, `PLW*`, `E402`,
  `E731`, `E741` — либо меняют поведение, либо вкусовые;
* `SIM108` отдельно: он требует тернарник ровно там, где тот становится
  вложенным, — прямой конфликт с S3358;
* `PLC0415` (импорт не на верхнем уровне) не включён вовсе: ленивые импорты
  здесь осознаны и их около семи тысяч;
* `ARG002`/`ARG003` выключены: «лишний» параметр метода — часть контракта
  (хуки тулов, `prompt_description(cls, config_dict)`).

В тестах дополнительно игнорируются `ARG`, `F841`, `SIM102`, `PLR0913`,
`B011`, `B017`, `RUF043`, `N815`, `ERA001`, `SIM115` — всё это жанровые
особенности наборов, а не дефекты.

## Снимок complexipy: замороженный долг

Функции сложнее 15 в `tui`, `server`, `mcp`, `testkit` (95 штук) записаны в
`complexipy-snapshot.json`. Это ratchet, а не амнистия:

* новое нарушение — коммит не проходит;
* упростили функцию — снимок сужается сам, ничего править не нужно;
* лезть в замороженное можно и нужно, но отдельной задачей (самый крупный
  кусок — `gc_tui`).

Снимок пересоздаётся так (только если список долга действительно поменялся):

```
uv run --group lint complexipy packages/tui/src packages/server/src \
    packages/mcp/src packages/testkit/src --snapshot-create --max-complexity-allowed 15
```

В `packages/core` и `packages/cli` замороженных функций нет и быть не должно.

## Как заглушить находку

Порядок предпочтений: исправить → выключить правило целиком с обоснованием в
`pyproject.toml` (если оно шумит без пользы) → и только потом построчная
заглушка. Засыпать код `noqa` вместо решения — плохой исход.

* ruff: `# noqa: <КОД>  # почему` — обоснование обязательно;
* наш чекер и Sonar: `# NOSONAR: почему` в той же строке;
* S107 (больше 13 параметров) для существующего кода — осознанный won't fix:
  `# noqa: PLR0913  # S107: won't fix, см. docs/code-quality.md`. Новые
  функции правило по-прежнему ловит.

Выключенная проверка TLS (`use_ssl: false` в config.yml) — не дефект, а
opt-in пользователя под корпоративный прокси с самоподписанным корнем. Такие
места помечены `NOSONAR` с обоснованием, в Sonar UI — «Won't fix / Safe».

## История форматирования

Коммит `style: ruff format` переформатировал почти весь репозиторий. Чтобы он
не мешал `git blame`, его хеш лежит в `.git-blame-ignore-revs`:

```
git config blame.ignoreRevsFile .git-blame-ignore-revs
```

## CI

Отдельный шаг CI — тот же `scripts/lint.sh` (он же `pre-commit run
--all-files`). Конфигурации CI в репозитории сейчас нет; когда она появится,
шаг добавляется дословно:

```yaml
- run: uv sync --group lint
- run: scripts/lint.sh
```
