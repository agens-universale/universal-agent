# TUI режим (`gc-ua`)

Кроссплатформенный терминальный интерфейс (TUI) поверх агента GigaCode. Запускается
отдельной командой `gc-ua`, существующий `gc-cli` не трогается: оба работают с одними
и теми же тредами, ядро агента не модифицируется.

## Установка

TUI-стек (`textual`, `rich`, `pygments`) и сам пакет `gc_tui` (вместе с подпакетом `diff_tui`) едет
дистрибутивом `gc-tui`. В профиле `gc-cli` их на диске нет вовсе:

```bash
uv tool install -e packages/tui
# без клонирования репозитория:
uv tool install "gc-tui @ git+https://gitverse.ru/gigacode-ai/universal-agent#subdirectory=packages/tui"
```

`pip install -e packages/tui` не сработает: манифест пинит `gc-core==0.3.0`,
который резолвится только через uv-workspace — pip пойдёт за ним на PyPI.

Полная таблица профилей — [Установка и запуск](usage.md#профили-установки), устройство — [упаковка](packaging.md).

Если TUI не установлен (профиль `gc-cli`), `gc-ua` печатает в stderr
однострочную подсказку с готовой командой и завершается с кодом 1 — без трейсбэка.

## Запуск

```bash
gc-ua                       # конфиг ищется как у gc-cli (config.yml)
gc-ua --config ./config.yml # явный путь к конфигу, прежняя семантика gc-cli
gc-ua --profile work        # активировать профиль work на этот запуск (поверх profile: из config.yml)
gc-ua --profile ""          # запуститься без профиля, ничего не потеряв — тот же совет даёт отказ сломанного конфига
gc-ua --init-config         # мастер настройки ~/.gc/config.yml; по завершении запускается TUI (Esc — выход без сохранения)
gc-ua --no-auto-mcp         # не поднимать HTTP/SSE MCP-daemon'ы при старте
```

По умолчанию `gc-ua` поднимает HTTP/SSE MCP-daemon'ы для серверов из `mcp-servers`
(пересечение с манифестом `recommended_mcp`); по выходе гасит только процессы этого
запуска. В `gc-cli` тот же автозапуск — только с явным `-a` / `--auto-mcp`.

> Флаг `--init-config` единообразен с `gc-cli --init-config`. Генерация `AGENTS.md` в TUI — команда `/init` в сессии (не флаг запуска). `--config`/`--profile` вместе с `--init-config` не учитываются: мастер всегда читает и пишет пользовательский `~/.gc/config.yml`.

## Главный экран

Краткий тур «с чего начать» — в README и на экране **F1** `/help` (секция «как работать»).

- **Шапка**: слева — имя задачи (`Сессия: <id>` + статус `[running]` / `[stopped]` /
  `[asking]`) и модель с режимом бэкенда (`модель: <model> · chat|resp`); справа —
  `F1 help · gc-ua`.
- **Бренд-блок**: логотип GIGACODE с теглайном `UNIVERSAL AGENT`  и версией строкой ниже, через отступ
  (`v0.0.1`; при запуске из исходников — `dev`, см. `app_version.display_version`) — остаётся вверху трейса.
  В правой колонке карточки — статус MCP (если серверы заданы), счётчик уведомлений
  (`⚠ N  ℹ M · F4/notices` — тот же бейдж, что в футере), строка `↑ доступна новая
  версия · /settings → Обновление` (если авто-проверка нашла обновление) и `✓ готов к работе`.
- **Трейс**: ход выполнения — реплики, tool-вызовы (`|- ok` / ошибки), мысли агента,
  системные события. Клик или Tab выделяет строку; Ctrl+клик или Enter открывает
  детальный экран вызова (аргументы + полный вывод). Правки файлов показываются
  диффом прямо в ленте. В строке-итоге хода — сводка правок
  (`изменено 3 файла · +120 −15`), при любом исходе хода: и после «Выполнил», и
  после ошибки, отмены или остановки — такой ход файлы тоже мог поменять; клик
  по ней открывает экран правок сразу в источнике «последний ход с правками». Имя инструмента в строке вызова — то, каким
  его зовёт реестр тулов (например, `fs_append_file`), а не внутренний
  идентификатор; длинный текст ошибки инструмента обрезается по границе
  слова с многоточием, а не посреди слова. Путь в аргументе строки вызова
  показывается путём всегда, а не длиной: длинный путь сжимается посередине
  с сохранением имени файла в хвосте; свёртка `<N chars>` осталась только
  для содержимого (`content`, `old`/`new`).
- **Поле ввода**: многострочное, плейсхолдер `опишите задачу или /команда`.
  Префикс `/` — slash-команды; одиночная `.` — та же палитра команд (удобно в
  RU-раскладке, без смены на `/`; дальше печатаете — палитра закрывается);
  префикс `!` — локальный shell (см. ниже); остальной текст — сообщение агенту.
- **Футер**: слева подсказки — `F1/help  F2/sessions  F3/diff  F5/config  F6/settings  F7/buffer`;
  при активном run слева остаётся ТОЛЬКО `Ctrl+C/stop` — F-подсказки на время хода
  уходят целиком (место нужно правой колонке: там переход модели и «запрос»);
  при непрочитанных уведомлениях — суффикс `· ⚠ N  ℹ M · F4/notices` (тот же бейдж,
  что в карточке: счётчики парой, точка только перед подсказкой); на узком окне блок
  уведомлений переносится вниз целиком и без ведущей точки — разделитель ставится
  только когда слева в той же строке есть сосед;
  справа — чем работаем (профиль, уровень, модель — см. ниже), заполненность контекста
  и, при наличии, usage/стоимость текущего запроса и сессии
  (`запрос <токены>/<цена> · сессия <токены>/<цена>`; знаки: `+` соединяет слагаемые
  суммы в разных валютах (`2.00$+200.0₽`), `~` — часть суммы посчитана по тарифу,
  `?` — есть трата, стоимость которой показать неоткуда; расшифровка в F1, блок
  «токены и стоимость», подробности — [usage_pricing.md](usage_pricing.md)).
  `/mcp` в базовый хром футера не входит (подсказка в карточке); `/diff` — F3
  и клик по сводке правок в строке-итоге хода.

**Чем работаем — правый край футера.** Слева направо: имя активного профиля (нет
профиля — ничего не показывается), **цветная точка** уровня (`light` · `default` ·
`max` — каждому свой цвет, те же цвета, что на треке `/level`) и имя модели, которой
пойдёт запрос. Имя — это алиас из реестра `models`, ваш собственный, а не длинный
провайдерский id (реестра нет — показывается модель из конфига).

Если переключить `/level` или `/profiles` **посреди хода**, точка и модель не
подменяются: агент доигрывает ход на прежней модели. Вместо этого появляется переход
`● модель → ● модель` — слева то, на чём ход идёт сейчас, справа то, что вступит в силу
со следующего. Уровень не менялся (сменился только профиль) — вторая точка не рисуется,
меняется только имя модели.

**Задача создаётся автоматически из первого сообщения** — просто опишите её текстом
и нажмите Enter. Следующие сообщения уходят в тот же тред; докидывать реплики можно
и во время работы агента.

Пока агент работает, внизу трейса виден анимированный индикатор активности — «компас-искра»:
точка `·` разворачивается во вращающийся треугольник `▴◂▾▸`, затем вспыхивает `✦` и гаснет;
рядом — текущая фраза (`думаю…`, `размышляю…` и др.) и счётчик времени `(Nс)`.
При финальной проверке ответа — `✦ завершаю… (Nс)`, во время сжатия истории — `⠋ сжимаю контекст… (Nс)`.

(`вы имели в виду /…?`).

### Переключатели в палитре

`/gate` и `/answers` — не команды, а переключатели: в открытой палитре ←/→ и
Enter меняют значение МГНОВЕННО (черновика нет) и применяют его к текущей
сессии сразу, без перезапуска и без правки `config.yml`. Esc просто закрывает
палитру — отменять нечего. Если палитра уже закрылась (набрали `/gate`
текстом, пробел, Enter) — значение не меняется: футер покажет текущее
значение и подсказку, как переключать через меню команд.

Переключатели в палитре действуют в текущей сессии: значение сохраняется в этом
разговоре и применяется при возврате к нему; новая сессия (`/new`) наследует то,
с чем вы работаете сейчас. В `config.yml` лежит глобальный дефолт — с него
стартуют сессии, у которых своего значения нет. Менять этот дефолт — в секции
«Режимы работы» экрана `/settings` (см. ниже): место управления определяет
область — палитра меняет сессию, Settings меняет глобальный дефолт.

Строка тоггла рисуется слайдером, а не текстом `on`/`off`: трек — глиф на
каждую позицию значения, применённое значение — закрашенный кружок `●` на
своей позиции, пустые позиции — незакрашенный `○`. 2 значения → `○ ●`/`● ○`,
3 значения → `○ ● ○`. Цвет кружка — не позиция, а смысл значения
(выключено/строго — белый, средний режим — амбер, включено/разрешено —
teal); подпись значения — своей колонкой справа от слайдера.

Пока выделена тоггл-строка, hint-строка футера вместо общей подсказки
палитры показывает значение и его смысл: `<значение> — <смысл> · ←/→/Enter —
переключить в текущей сессии` — область действия встроена прямо в клавишную
часть подсказки, а не отдельным сегментом. При переключении ←/→/Enter подсказка
меняется на лету вслед за применённым значением; на узком терминале укорачивается
по ступеням — сначала уходит «кому подходит», затем клавиши теряют область целым
куском (`переключить в текущей сессии` → `переключить`), затем клавиши сжимаются
до `←/→/Enter`, дальше — многоточие на смысле. Механика (клавиши в той или иной
форме) видна всегда; глобальный дефолт по-прежнему меняется в секции «Режимы
работы» экрана `/settings`.

| Тоггл | Описание |
|---|---|
| `/gate` | `Самопроверка выполнения задачи: закрыт ли запрос` |
| `/answers` | `Формат ответа: допустим ли текст как финал хода` |

| Тоггл | Значение | Подсказка |
|---|---|---|
| `/gate` | `on` | `самопроверка не даст закончить, пока запрос не закрыт · для сложных задач, где важна полнота` |
| `/gate` | `off` | `самопроверка выключена · быстрее: для простых задач и экономии токенов` |
| `/answers` | `allow` | `текстовый ответ всегда принимается · для чата и быстрых ответов` |
| `/answers` | `judge` | `текстовый ответ принимается, если проходит самопроверку · универсальный режим` |
| `/answers` | `deny` | `текст не завершает ход: агент обязан закончить вызовом инструмента · для строгой автономии` |

В палитру-переключатели попадают только ручки, которые (1) меняют посреди
сессии, (2) имеют простое значение, (3) безопасны для горячего применения.

Второй вход к тем же тогглам — секция «Режимы работы» в `/settings` (см.
ниже). Место управления определяет область: палитра меняет текущую сессию,
секция Settings меняет глобальный дефолт в `config.yml`. Агент всегда видит
эффективное значение = глобальный дефолт + оверрайд сессии.

### `/level` и `/profiles` — чем работаем

Два переключателя над группой строгости — про модель, а не про поведение. Оба
действуют **в текущей сессии** и ничего не пишут в `config.yml`; глобальные значения
живут в конфиге (ключи `level` и `profile`) и меняются в `/settings`: уровень — в
секции «Режимы работы», активный профиль — в секции «Профили». См.
[Конфигурация](configuration.md#профили-и-уровни-моделей).

**`/level`** (синоним `/models`) — обычный тоггл с треком из трёх позиций:
`light` · `default` · `max`. Подсказка палитры для каждой позиции показывает не
абстрактный уровень, а **что за ним реально стоит** в конфиге: алиас модели плюс
назначение уровня («быстрая и дешёвая: простые задачи» и т. д.). Если слот не задан и
сработала подстановка соседнего, подсказка честно показывает цепочку
(`glm-local (light → default)`), а не притворяется. Особые состояния тоже названы прямо:
реестра моделей нет — `легаси: уровни появятся с реестром моделей`; запуск с `--model` —
`--model: уровни отключены на этот запуск`; модель попала в предохранитель —
`<алиас> недоступна (предохранитель) · переключите /profiles`.

**`/profiles`** — не трек, а список: значения берутся с диска (файлы профилей из обоих
корней) плюс строка «без профиля». У каждой строки — свой статус: `● активен` у той,
что действует сейчас, `✗ не применится` — у профиля, с которым конфиг не собирается
(тот же судья, что у гейта выбора). Подсказка строки для такого профиля первой строкой
называет причину, а дальше, как обычно, — состав слотов профиля, его источник
(проектный / глобальный) и, если профиль переопределяет MCP-серверы, предупреждение о
цене переключения. Enter открывает список выбором; можно и сразу именем —
`/profiles work`. Имени нет среди найденных — команда честно отказывает и перечисляет
доступные; выбор профиля, с которым конфиг не собирается, отклоняется так же —
и Enter, и `/profiles <имя>` отказывают ДО применения (`✗ не сохранено: <причина>`),
сессия остаётся на прежнем профиле.

Переключение посреди работы агента не обрывает ход: текущий ход доигрывается на прежней
модели (уровень фиксируется в начале хода), а в уведомлениях появляется
`применится после завершения текущей задачи`. Профиль может задавать и такие ключи,
которые подхватываются только при старте (каталоги тредов и логов) — про них тоже
приходит отдельное уведомление.

Палитра только переключает. Завести профиль, переименовать, удалить и отредактировать
его секции моделей можно в `/settings` → «Профили» (см. ниже).

### `/rigor` — строгость завершения хода

Одна ручка вместо двух: `low` (быстро и дёшево), `medium` (универсально,
дефолт поставки), `high` (тщательно). `/rigor` — витрина над самопроверкой
(`/gate`) и форматом ответа (`/answers`): пресет одновременно ставит обе
настройки; палитра крутит текущую сессию, /settings — глобальный дефолт.

Подвал палитры по умолчанию — строка `/rigor` и сразу под ней, ВСЕГДА
(независимо от выделения и от навигации курсором), её дети `/gate` и
`/answers` — плоско, без отступа, серыми (DIM) строками: иерархия читается
только цветом, а не позицией — состав подвала статичен, высота палитры не
скачет. Крутите пару целиком через `/rigor` или отдельный ключ через
`/gate`/`/answers` — они переключаются на своей строке как обычные тогглы.
То же в секции «Режимы работы» экрана `/settings`: дети `gate`/`answers` —
без маркера и без отступа, тем же левым краем, что и родитель, тоже серые.
Независимые группы тогглов-пресетов (когда появятся) разделяются чертой между
соседними группами — тот же родовой приём в палитре и в Settings; сегодня
группа одна (`/rigor`) — черты не видно.

`/rigor` крутится строго по трём значениям (`low`/`medium`/`high`) — так же,
как в Settings; `custom` не выбирается ни стрелками, ни Enter. Как только
пара `/gate`+`/answers` перестаёт совпадать ни с одним пресетом (накрутили
детьми нестандартную комбинацию), `/rigor` сам показывает `custom` на
зарезервированной 4-й позиции трека — место под неё есть всегда, колонки не
сдвигаются, когда custom появляется или гаснет. Шаг стрелкой с отображаемого
`custom` уводит на пресет и заменяет пару целиком; отдельного «вернуться к
глобалу» из палитры нет — вернуть глобальные значения можно, выставив их
обратно детьми `/gate`/`/answers`.

Значение самопроверки `smart` (`/gate`, дефолт): судья проверяет полноту ответа
только если за ход был хотя бы один вызов инструмента; разговор без действий не
проверяется.

## Просмотр файла (`/view`)

`/view <path>` открывает отдельный экран постраничного просмотра текстового
файла (не shell и не агент). Относительные пути — от cwd TUI; чтение через
Python FS (кроссплатформенно). Управление: **↑↓** (строка), **PgUp/PgDn**
(страница), **Esc** — назад. Для известных расширений (`.py`, `.yml`, …) —
подсветка синтаксиса текущего окна (`rich.syntax`, как в `/config`); plaintext
без подсветки. Бинарники и файлы больше лимита не показываются — сообщение в
теле того же экрана. Пока жив процесс TUI, повторный `/view` того же файла
открывает ту же страницу (позиция только в памяти процесса).

Конфиг: `tui.file_view` (`enabled`, `max_file_bytes` по умолчанию 64 MiB;
`page_lines`: `null` = авто по высоте экрана, число = фиксированный шаг).

## Shell (`!`)

Префикс `!` в поле ввода выполняет команду в **системном shell** (`/bin/sh` на
POSIX, `cmd.exe` на Windows) в текущей рабочей папке TUI (та же, что справа в
футере). Это не агент и не tool-call: вывод появляется в трейсе как `[!] $ …` и
**не** пишется в thread / export / session log (после rebuild трейса строк нет).

Примеры: `! git status`, `!echo hello` (пробел после `!` опционален).

`! clear` убирает из трейса все блоки bang-вывода; `! clear 3` — последние
три. Сама команда в трейс не пишется. Пока идёт другой `!` — clear отклоняется.

Ограничения MVP:

- non-interactive: без PTY, stdin закрыт; `vim` / `nano` / `docker -it` /
  `sudo` / `su` и аналоги отклоняются до запуска;
- один concurrent `!`; пока команда идёт — **Esc**, **Ctrl+C** или `/stop`
  отменяют её (Esc не выходит из TUI);
- во время ask_human текст с `!` уходит как ответ агенту (приоритет вопроса);
- `! cd …` меняет cwd только дочернего shell, не TUI.

Конфиг: `tui.bang_shell` (`enabled`, `timeout_sec`, `max_output_bytes`,
`max_output_lines`). При `enabled: false` — отказ в трейсе, текст **не** уходит
агенту.

`/skill <id>` без запущенной задачи откладывает навык до следующего сообщения;
во время run — отправляет агенту сразу. `/skill <id> <текст>` — навык + промпт
одним ходом.

`/export` без аргумента — `txt`; файл `export-<id>-<метка времени>.<fmt>` пишется
в текущую папку:

| Формат | Содержимое |
|---|---|
| `txt` | читаемый аннотированный лог сессии |
| `json` | структурированные данные сессии |
| `log-txt` | копия лог-файла агента текущего запуска (`.log`) |
| `log-json` | сырой jsonl треда целиком (все сегменты) |

`/compact` — принудительное сжатие в режиме `chat_completions` (в `responses`
недоступен). Работает только на паузе между run'ами; повтор без новых сообщений
после прошлого сжатия отклоняется.

## Голосовой ввод (`/voice`, Ctrl+T)

`Ctrl+T` начинает диктовку: пока идёт запись, поле ввода обведено, а над ним —
пилюля с уровнем сигнала и подсказкой `Ctrl+T / Enter — стоп · Esc — отмена`.
Стоп отправляет запись на распознавание и **вставляет текст в поле ввода** —
отправку вы делаете сами, как обычно. Esc отменяет запись, ничего не распознавая.

Запись сама останавливается на `voice.max_seconds` (по умолчанию 120 с) —
предохранитель от забытого микрофона.

Распознаёт не агент, а STT-сервис, и он бывает двух видов:

- **локальный** — «батарейка» на вашей машине (`gc-voice install`, ~0.9 ГБ на
  диске). Работает без сети и без ключей, поднимается сам при старте `gc-ua`;
- **облачный** — любой endpoint, совместимый с `/v1/audio/transcriptions`.
  Нужен адрес, а токен — если сервис его требует.

Выбор режима и все поля — в секции **«Голосовой ввод»** экрана `/settings`,
там же проверка связи (`Ctrl+Space`) и установка/снос локального сервиса.
Ключи конфига — в [`configuration.md`](configuration.md), секция `voice:`.

Версия локального движка привязана к версии агента. Когда она отстаёт, строка
«Локальный сервис» показывает `· доступно vX.Y.Z`, а **Ctrl+U** («обновить версию»,
та же клавиша и тот же глагол, что у MCP-серверов) обновляет движок
(порт и модель сохраняются; сервис гасится на время обновления и поднимается снова).
То же предлагает экран после обновления агента, а `gc-voice status` называет
отставание в консоли.

## Хоткеи

- **Enter** — отправить сообщение.
- **Ctrl+J** — перенос строки (в терминалах с Kitty protocol / modifyOtherKeys
  также **Ctrl+Enter** / **Shift+Enter**).
- **Esc** — «лестница», всегда разбирает самый локальный контекст:
  1. открыт пикер/палитра → закрыть;
  2. идёт bang-shell (`!`) → отменить команду (`[!] cancelled`);
  3. в поле есть текст → подсказка `Esc ещё раз — очистить` (второй Esc в течение
     2 секунд очищает поле);
  4. поле пустое, агент ждёт ответа (ask_human) → остановить тред;
  5. поле пустое, идёт run: если агент ещё ничего не выдал — мгновенная отмена
     с откатом (реплика убирается, текст возвращается в поле ввода); иначе подсказка
     `Esc ещё раз — остановить`;
  6. поле пустое, run не идёт → подтверждение выхода (`Завершить сессию?` Y/N).
- **Копирование выделенного** (в поле ввода или в трейсе) во внешний буфер ОС:
  - **основной жест** — выделить мышью **без Shift** (copy-on-select); внутри
    блоков кода и таблиц выделение посимвольное — можно взять часть блока, а
    не только целиком;
  - **Ctrl+C** — если есть выделение, копирует; если нет — останавливает текущий run
    (или exit-модалка вхолостую);
  - **Ctrl+Shift+C** (и **Cmd+C** / Super+C, если жест дошёл до приложения) —
    копирует выделение без stop; терминал часто перехватывает хоткей — страховка,
    не замена copy-on-select;
  - **Кнопка копирования** в шапке блока кода, таблицы или диффа правки —
    копирует блок целиком: код без обрамления ```` ``` ````, таблицу в
    markdown (с трубами `|`), дифф — с именем файла в заголовках
    (`--- a/<путь>` / `+++ b/<путь>`), патчем, применимым командой `git apply`
    или `patch`. Исключение — файл вне проекта, у которого путь в записи
    абсолютный: заголовки остаются пустыми, потому что `a/<абсолютный путь>`
    всё равно никуда не применяется, и подставлять его значило бы обещать
    применимость, которой нет. Слева от кнопки в шапке кода — язык. После нажатия на
    полторы секунды показывает ✓.
    Глиф кнопки подбирается под терминал: `⧉` там, где терминал умеет подставлять
    недостающие символы из других шрифтов (Windows Terminal, встроенный терминал
    VS Code, терминалы Linux и macOS), и `❐` в старой консоли Windows, где шрифт
    один и `⧉` в нём отсутствует;
  - **Двойной клик** по блоку — выделяет его целиком и копирует (то же
    содержимое, что у кнопки): для таблицы это markdown, а не псевдографика
    (псевдографику с `│` даёт только выделение мышью части блока). Двойной
    клик сам по себе тоже выделение, поэтому отменяет отложенную автокопию
    выделенного — иначе она сработала бы позже и затёрла markdown тем, что
    видно на экране;
  - с экранов `/view` и visual `/diff` к тексту в буфере дописывается суффикс
    источника: `[file: path]` или `[diff: path]`;
  - **Linux локально:** чтобы вставлять в другие программы, нужны `wl-clipboard` /
    `xclip` / `xsel` (иначе предупреждение раз за сессию). Без них внутри `gc-ua`
    копирование и Ctrl+V работают; наружу: Ctrl+V в поле ввода → Shift+мышь →
    Ctrl+Shift+C / Cmd+C в окне терминала. **SSH:** клиентский буфер через OSC 52
    (разрешите в терминале; в tmux — `set -g set-clipboard on`);
  - **Shift+мышь** — выделение окном терминала (запасной способ, не через приложение).
- **Три буфера** (в каждой сессии — свой):
  - **TUI** — внутренний буфер приложения (copy-on-select и Ctrl+C). Чтение —
    Ctrl+V / правый клик внутри TUI.
  - **Сессии** — накапливающий буфер, хранится в метаданных сессии
    (`tui.copy_buffer`). Дописывается явными жестами копирования — **Ctrl+C** и
    **кнопкой копирования** — сверху, между кусками пустая строка; лимит 20 000 символов
    (старые куски выкидываются снизу целиком). На экране превью чужой сессии
    кнопка копирования копирует наружу, но в буфер сессии не пишет — своей активной
    сессии там нет. Чтение — `/buffer` или **F7**.
  - **ОС** — системный буфер (`copy_out` → native, либо Shift+drag). На
    Win/Mac обычно синхронизирован с TUI; на Linux нужны `wl-clipboard` / `xclip` / `xsel`.
  - Не успели Ctrl+C → текст в TUI (и часто в ОС) → `/buffer` → Ctrl+V / RMB.
- **F7** — открыть буфер сессии (`/buffer`). Большое текстовое поле на весь
  экран, длинные строки переносятся, скролл мышью и клавишами. **Esc —
  сохранить и закрыть** (пустой текст = очистили буфер; без изменений на диск
  не пишем). Вставка: Ctrl+V / Ctrl+Shift+V / правый клик — сначала из буфера
  ОС, пусто — из внутреннего буфера TUI. Выделение/Ctrl+C на экране буфера
  копирует наружу, но не дописывает буфер сам в себя. Нет активной сессии —
  короткое сообщение, экран не открывается. F7 при открытом буфере — no-op.
- **F1** / **Ctrl+/** — справка, **F2** / **Ctrl+S** — сессии,
  **F3** / **Ctrl+D** — правки агента, **F4** / **Ctrl+O** — уведомления,
  **F5** / **Ctrl+G** — конфиг, **F6** — настройки, **F7** — буфер сессии,
  **Ctrl+N** — новая сессия,
  **Ctrl+R** — переименовать активную сессию (пустое имя → авто-имя из
  `last_actual`; на той же раскладке — `Ctrl+к`).
- **Ctrl+T** — голосовой ввод: старт диктовки, повторное нажатие (или **Enter**) —
  стоп и распознавание, **Esc** — отмена записи (см. «Голосовой ввод» выше).
- **Ctrl+A** — выделить всё в поле ввода (на экране правок — принять все
  активные файлы представления; там же `a` — принять файл, `u` / `Ctrl+U` —
  отменить принятие, `r` / `Ctrl+R` — откат).
- **↑ / ↓** — история ввода (per-project; ↑ работает с первой строки поля,
  ↓ — с последней; за самой свежей записью возвращается черновик).
- **Tab** — подставить выбранный пункт открытого пикера/палитры.
- **Ctrl+V** — вставка из системного буфера. Крупная вставка сворачивается в плашку
  (`[Вставка #N · K строк]`); повторный Ctrl+V тем же текстом в короткое окно разворачивает
  её инлайн (подсказка в футере: `вставьте ещё раз — развернуть`). Плашка ведёт себя
  как один символ: Backspace/Del удаляют целиком, при отправке разворачивается.
- **Правый клик** — тоже вставка из системного буфера (нативная вставка терминала
  перехватывается mouse-reporting, поэтому обрабатывается самим приложением).
- **Ctrl+клик / Enter** на строке tool-вызова или реплики — открыть полный payload;
  обычный клик выделяет строку (как Tab).

### Клавиши на macOS

На клавиатуре Mac клавиша ⌫ подписана `delete` и стирает влево (аналог Backspace на PC);
терминал доставляет её приложению как Backspace.

| Действие | Клавиши | Примечание |
|---|---|---|
| Удалить слово слева | `Option+Delete (⌫)` или `Ctrl+W` | в iTerm2 включите Profiles → Keys → Option key: `Esc+` (Terminal.app: Use Option as Meta) |
| Удалить до начала строки | `Ctrl+U` | `Cmd+Delete` до приложения не доходит (перехватывает терминал); привычный жест можно вернуть маппингом в iTerm2: Cmd+Delete → Send hex `0x15` |
| Копировать выделенное (мышью или в поле ввода) | выделить мышью / `Ctrl+C` | copy-on-select или хоткей → системный буфер (pbcopy) |
| Копировать выделение терминала (`Shift+drag`) | `Cmd+C` | средствами терминала; до приложения Cmd-сочетания часто не доходят |

## Пикеры

- **Палитра команд** — открывается при вводе `/`, фильтруется по мере набора;
  ↑↓ — выбор, Tab — подставить, Enter — выполнить, Esc — закрыть.
- **Skill picker** — открывается после `/skill ` (пробел за командой); список навыков
  с фильтрацией, тот же контракт клавиш.
- **Arg picker** — для команд с фиксированными значениями аргумента
  (например `/export ` → `txt` / `json` / `log-txt` / `log-json`).
- **File picker (@-упоминания)** — символ `@` в тексте открывает выбор файла:
  fuzzy-поиск по корню проекта, `@dir/` — листинг каталога. Tab достраивает путь
  (папка — остаётся в пикере, файл — закрывает). Упомянутые `@path` файлы при отправке
  прикладываются агенту как контекст.

## Уведомления (`/notices`, F4)

Неблокирующие замечания: стартовые (конфиг, MCP, pricing и т.п.) и runtime
(ошибки LLM и прочие события сеанса). Детали — на экране `/notices` (F4), трейс
ими не засоряется.

- в бренд-карточке и футере — бейдж `⚠ N  ℹ M · F4/notices`;
- экран `/notices` — полный список (read-only); после просмотра бейджи
  «новых» runtime-уведомлений гаснут;
- `Esc` — назад.

## Правки агента (`/diff`, F3)

Экран показывает, что агент сделал с вашими файлами: список файлов со
счётчиками, дифф каждого файла, принятие и откат. Чужих правок здесь нет —
только то, что записал сам агент (инструментами или shell-командами).

Экран изменений показывает файлы ПРОЕКТА. Правку файла за его пределами видно
в ленте — диффом под строкой вызова, — но на экран она не попадает: базы для
отсчёта у такого файла нет, поэтому ни принять, ни откатить его нельзя.
Служебные каталоги и файлы-инструкции не отслеживаются вовсе.

**Git-репозиторий и обычная папка.** Правки инструментов отслеживаются везде
одинаково: журнал, точный снимок «до», принятие и откат. В обычной папке
отличий два: ступени «закоммичено» нет, а принятие не добавляет файл в индекс
git. Правки shell-команд устроены иначе. В git-репозитории команда видна
целиком — по статусу git до и после неё. В обычной папке статуса нет: перед
каждой командой в память снимаются только файлы, которые журнал уже знает (до
100 самых недавних), и только их правки команда покажет. Файл, созданный
командой, или файл, которого агент раньше не касался, в обычной папке на экран
не попадает. Git-режим включается, когда в корне проекта есть `.git` и
установлен сам git; вложенный репозиторий режим не меняет.

**Два источника.** Переключаются на месте, `Shift+Tab`, без открытия нового
экрана:

- **сессия** — итог от ближайшей точки отсчёта (см. «Лестница точек отсчёта»
  ниже);
- **последний ход с правками** — итог последнего хода, в котором правки были:
  ход без правок записей в журнал не оставляет и потому этому источнику не
  виден вовсе. Подпись называет это прямо — короткое «последний ход» обещало
  буквально последний и вводило в заблуждение.

Шапку с базой счёта видно только у источника «последний ход с правками» — там она одна
на весь список: `изменения · последний ход с правками · от начала хода · N файлов · +A
−R`. У источника «сессия» шапка базу не называет: у каждого файла своя
ближайшая ступень (см. ниже — глиф `↺` или короткий хэш коммита в строке),
и общая фраза в шапке была бы неправдой. Хвост шапки — `N файлов · +A −R`,
пока активных файлов хоть один; на нуле активных при живой группе
разобранных — `новых изменений нет`; голое «изменений нет», без слова
«новых», — только когда нет вообще ничего, ни активных, ни группы.

**Команда, тронувшая слишком много файлов.** Одна команда записывается в
журнал не больше чем 10 000 путями — остальные экран не видит и откатить не
может. Тогда над списком стоит строка-предупреждение: `⚠ Одна из команд этой
сессии изменила 12000 файлов — в список попали не все: остальные здесь не
видны, откатить их отсюда нельзя.` Сама она не гаснет: файлы сверх потолка не
записаны, и узнать, что с ними стало, экрану нечем. Прочитав, её можно скрыть
клавишей `x` (подсказка `x — скрыть` стоит в конце строки) — до выхода из
gc-ua, сразу в обоих источниках: команда та же. Если позже в потолок упрётся
другая команда, строка появится снова — уже про неё. В источнике «последний
ход с правками» строка есть, только если такая команда была в этом ходе.

### Лестница точек отсчёта

У файла есть несколько точек, от которых экран умеет считать «что
изменилось»: **начало сессии → принято → закоммичено → диск**. Чем выше
ступень, тем она новее; счёт и откат источника «сессия» всегда идут от
ступени, ближайшей к текущему содержимому файла, — а не всегда от самого
начала сессии.

- **Начало сессии** — снимок, который экран берёт сам при первой правке
  агента по этому файлу в этом диалоге. Хранится всегда и никуда не
  девается: на эту ступень можно опереться, даже если из перечисленного ниже
  вы ничего не делали.
- **Принято** — вы объявляете её сами, клавишей `a` (файл) или `Ctrl+A` (все
  активные файлы представления): «то, что сейчас на диске, — новая точка
  отсчёта, дальше показывай только то, что изменится поверх неё». Появляется
  только по вашей команде.
- **Закоммичено** — появляется сама, если файл отслеживается git и его
  затронул коммит (ваш или сделанный агентом shell-командой), случившийся
  уже после начала сессии. Отдельно нажимать ничего не нужно. Ваши правки,
  сделанные руками до начала сессии и не закоммиченные, ступени не создают:
  коммита не было, и откат вернёт файл к началу сессии — вместе с этими
  правками, а не поверх них. Содержимое этой ступени берётся в тех концах
  строк, что сейчас у файла на диске, и откат запишет ровно те байты, с
  которыми сравнивал: файл, написанный агентом с `LF` и закоммиченный без
  выкладки, не покажется целиком заменённым и не поменяет переводы строк при
  возврате.
- **Диск** — не ступень лестницы, а то, что в файле прямо сейчас; с ним и
  сравнивается каждая ступень.

Файл, который агент **создал** в этой сессии, снимка «до» не получает вовсе
— начало сессии для него равно пустоте. Если такой файл успели закоммитить,
а агент потом правил его ещё раз, ступень «закоммичено» всё равно
появляется: момент создания экран запоминает отдельной отметкой, и правка
после коммита считается от закоммиченного содержимого, а не от пустоты
целиком. Пока коммита не было, созданный файл по-прежнему считается от
пустоты — это правило остаётся без изменений.

Если файл и принят, и закоммичен, ближайшей к диску считается та ступень,
что случилась позже, — принятие после коммита обгоняет его, а коммит после
принятия обгоняет принятие.

**`r` / `Ctrl+R` — откат.** Возвращает файл на диске к ближайшей ступени
лестницы, а не всегда к началу сессии. Подтверждение прямо называет цель:
«вернёт к принятому состоянию», «вернёт к закоммиченному состоянию», «вернёт
к началу сессии» — какая из них сработает, зависит от того, что реально
случилось с файлом. Подсказка футера называет ту же цель короче, прямо на
строке действий: `r откат — вернуть файл к началу сессии` (у «Хода» — «к
началу хода», у коммит-ступени — «к закоммиченному»), а на принятом файле —
`r откат — вернуть к принятому`; какой из вариантов показан, всегда
совпадает с действующей ступенью файла под курсором. У файла без
достоверной базы отката `r` в подсказке футера не показывается вовсе — по
тому же канону, что и остальные неприменимые клавиши этого экрана.

Хвост массовых клавиш в конце строки действий — один и тот же на любой
строке, включая строку группы, и каждая клавиша названа глаголом: `Ctrl+A
принять все` виден, пока в представлении есть хоть один активный файл;
`Ctrl+R откатить все` — пока хоть у одного файла представления есть
достоверная база отката; `Ctrl+U сбросить все принятия` — пока в
представлении есть хоть одно принятие: среди активных файлов есть хоть один
с принятой базой — даже если действующая ступень у него уже другая (коммит)
или источник «Ход», где ступень не показывается вовсе, — либо файл принят
вручную и до сих пор лежит в группе разобранных. Неживая клавиша из хвоста просто уходит — тем же каноном, что и
у одиночных `a`/`u`/`r`.

**`u` / `Ctrl+U` — отменить принятие.** Снимает ступень «принято» (у одного
файла или сразу у всех файлов, принятых вручную). Снимок начала сессии при
этом не трогается — он хранится всегда, поэтому передумать можно в любой
момент. Снять принятие можно и из источника «ход» — отменяется та же
ступень «принято» у базы «сессии», но сам «ход» этого не показывает (его
точка отсчёта всегда «начало хода»), поэтому плашка в этом случае тоже
называет источник, где отмена реально видна: `эффект виден в «Сессии» —
«Ход» по-прежнему считает от начала хода`. После отмены счёт идёт от
ближайшей из оставшихся ступеней: если
файл успели ещё и закоммитить — от коммита, иначе — снова от начала сессии.
Если хоть у одного файла на диске есть правки поверх принятого (дельта от
принятой базы непуста либо сравнить её нечем), `u` / `Ctrl+U` вместо
мгновенного действия открывают полноэкранное подтверждение — тот же жанр,
что у отката (см. ниже): дерево блоков без курсора и выделения — на этом
экране нет действия на отдельный файл, только решение по всему набору.
`u` держит имя файла в шапке и обходится без блока (файл один, повторять
имя в теле незачем); `Ctrl+U` называет блоком КАЖДЫЙ файл, даже
единственный, — и те, что ничем не рискуют, тоже. Блок несёт две строки:
чего файл лишается («точка отката к принятому состоянию (14:20) будет
потеряна» либо «терять нечего») и откуда после сброса пойдёт счёт («после
сброса счёт пойдёт от начала сессии» либо «…от закоммиченного состояния»);
между блоками — пустая строка. `↑↓` и `PgUp`/`PgDn` листают тело, когда оно
не помещается в кадр целиком, — иначе подсказка прокрутки в футере не
показывается. Esc отменяет — принятие остаётся; `Enter` подтверждает и
называет объём набора прямо на себе — `Enter сбросить 2 файла` — принятие
снимается. Диффа на этом экране нет вовсе (сброс не пишет на диск) — только
цена и цель. Если точку отката не теряет ни один файл, экран не
открывается — сброс срабатывает сразу.

**Коммит — граница экрана.** Отменять закоммиченное — работа git
(`git revert`), а не этого экрана: откат источника «сессия» никогда не
уводит файл ниже ступени «закоммичено». Закоммиченное удаление — тоже
ступень: файл, удаление которого уже в коммите, откат не вернёт, а файл,
пересозданный после такого коммита, откат удалит. Исключение одно — источник «ход»:
его точка отсчёта всегда «начало хода», и если после начала хода появилась
более новая ступень (агент сам закоммитил файл командой, либо вы приняли или
закоммитили его вручную уже после хода), откат «хода» её заденет. Экран
такой откат не блокирует — он показывает предупреждение и оставляет решение
вам.

**Откат никогда не переписывает историю git.** `r` и `Ctrl+R` возвращают на
диск только содержимое файлов — коммиты остаются как были в любом случае.

Что отменяет каждое действие:

| Действие | Отменяет | Не трогает |
|---|---|---|
| `r` / `Ctrl+R` — откат | содержимое файла на диске — возвращает к ближайшей ступени лестницы | коммиты git — никогда |
| `u` / `Ctrl+U` — отменить принятие | ступень «принято» — счёт продолжается от следующей ступени вниз | файл на диске и коммиты |
| `git revert` (вручную, вне экрана) | сам коммит в истории git | это единственный способ отменить закоммиченное — экран им не занимается |

**Счётчики — итог по файлу, а не сумма шагов.** Файл, правленный за ход трижды,
показывает разницу «было → стало», а не сложенные три правки. Пометки в строке
файла говорят то, что стоит знать:

| Пометка | Что означает |
|---|---|
| `создан` / `удалён` / `изменён` | что случилось с файлом за представление |
| `командой` | среди правок есть сделанные shell-командой |
| `извне` | среди правок есть сделанные мимо агента — вами руками или другим процессом |
| `≈` перед счётчиками | точного снимка «до» нет, числа собраны из отдельных правок |

Знаки, которые на экране реально есть, шапка расшифровывает сама: `↺ от
принятого`, `хэш — от коммита`, `извне — есть правки не от агента`. Пустых
расшифровок не бывает, а на узкой ширине легенда жертвуется первой.

Расшифровка `извне` говорит о наличии чужих правок и не называет их долю.
Доли мы не знаем: видимый дифф может состоять из чужих строк целиком — если
агент правил файл раньше, а потом его работу затёрли. «Весь файл чужой» при
этом невозможно по построению: путь попадает на экран только через журнал
правок агента. Ту же фразу несёт шапка вьюера, чтобы предупреждение не
исчезало ровно тогда, когда смотрят содержимое.

В источнике «сессия» активный файл со ступенью «принято» помечен глифом
`↺` сразу после счётчиков — это значит, что его счёт и откат идут не от
начала сессии. Файл, который вместо этого считается от коммита (ступень
«закоммичено»), несёт в том же месте приглушённый короткий хэш коммита —
оба знака сразу не бывают, действующая ступень у файла всегда одна. В
источнике «ход» этой пометки нет ни у кого: там счёт всегда идёт от начала
хода, а принятие и коммит на него не влияют.

Шапка вьюера называет действующую ступень прямо — «счёт от принятого
состояния (14:32)» либо, симметрично, «счёт от закоммиченного состояния
(e5f2c1a · 14:20)»; подтверждение отката говорит о том же другими словами —
«вернёт к принятому состоянию (14:32)» / «вернёт к закоммиченному состоянию
(e5f2c1a · 14:20)».

**Разобранные файлы сворачиваются.** Файл, на который смотреть больше нечего
(принят и чист, либо просто чист относительно последнего коммита), уходит
вниз списка в одну строку вида `▸ принято 3 · закоммичено 1`. Общего слова
на всю группу нет: коммит происходит без вашего участия на этом экране, и
подписывать его тем же словом, что ручное принятие, было бы неправдой.
Нулевые сегменты не показываются — если разобранные только одной категории,
в строке видна только она. Enter или клик раскрывает её (`▾`): внутри — те
же файлы приглушённым цветом, в колонке вида — причина (`принят` для
файлов, которые вы приняли, `закоммичен` — для тех, что разобрались
коммитом), счётчики — кумулятив за всю сессию (что агент сделал с файлом
всего, а не с последней ступени); как и у активных строк, эти счётчики тоже
могут нести `≈` перед собой, если точного снимка для сравнения нет и числа
собраны из отдельных правок журнала. Новая правка агента поверх разобранного
файла возвращает его в активные автоматически, без каких-либо действий с
вашей стороны.

Клавиши экрана:

| Клавиша | Действие |
|---|---|
| `↑` `↓` `PgUp` `PgDn` `Home` `End` | выбрать строку (файл или строку группы) |
| `Enter` | обычный/принятый файл — дифф; строка группы «принято» — развернуть/свернуть; файл внутри группы — что агент сделал с ним за сессию |
| `Shift+Tab` | переключить источник: сессия ↔ последний ход с правками |
| `Tab` | переключить область: активные файлы ↔ строка группы (только если группа есть) |
| `a` / `Ctrl+A` | принять выбранный файл / все активные файлы представления |
| `u` / `Ctrl+U` | отменить принятие выбранного файла / всех принятых вручную |
| `r` / `Ctrl+R` | откатить выбранный файл / всё представление |
| `x` | скрыть строку-предупреждение о команде, тронувшей больше 10 000 файлов (до выхода из gc-ua) |
| `Esc` | назад |

`Enter` называется по строке под курсором и живёт в строке действий футера —
той половине, что меняется вместе с курсором: `Enter дифф` на обычном и
принятом файле, `Enter развернуть` / `Enter свернуть` на строке группы
«принято» (по её текущему развороту), `Enter — что агент сделал с файлом за
сессию` на файле внутри группы. Строка навигации (`↑↓`/`PgUp`/`PgDn`/`Home`/
`End`, `Shift+Tab`, `Tab`, `Esc`) от курсора не зависит — она называет то, что
зависит от состояния экрана целиком.

`Tab` переключает курсор между активной частью и группой и помнит позицию в
обеих: он вернёт вас и на ту строку активной части, с которой вы ушли, и на
тот файл группы, на котором стояли, — а если группу с тех пор свернули или
файл из неё ушёл, то на строку группы. Клавиша работает, только когда есть
что переключать: без группы или при пустой активной части она молчит и не
показывается в подсказке футера.

Внутри раскрытой группы `r` не работает ни у кого (отменять уже нечего — файл
разобран), `u` — только у файлов, принятых вручную; разобранные коммитом
снимаются лишь тем, что умеет git. В подсказке футера `u` следует тому же
правилу: она не показывается ни на строке заголовка группы (ступени
«принято» у неё нет — снимать нечего), ни у файла, разобранного коммитом.

Во вьюере файла: `n` / `p` — к следующей и предыдущей правке, `←` / `→` —
соседний файл источника, `f` — показать файл целиком и обратно, `a` —
принять читаемый файл, `u` — отменить его принятие, `r` — откатить его,
`Esc` — назад. Действия вьюера — только над тем файлом, который вы читаете:
массовые `Ctrl+A` / `Ctrl+U` / `Ctrl+R` живут в списке, где виден весь набор.
У открытого файла без достоверной базы отката вьюер тоже прячет `r` — тем же
признаком, что и список; название клавиши в футере от этого не меняется
(`r откат`, без цели) — саму базу называет заголовок вьюера.
Вьюер, открытый из группы разобранных файлов, показывает кумулятивный дифф за
всю сессию и листает `←`/`→` только файлы группы; `a` и `r` там не работают
(дифф от ступени пуст), `u` работает у файлов, принятых вручную. Текущая
правка помечена акцентной полосой слева, в шапке стоит её номер (`правка
2/4`); `n` с последней ведёт на первую. Полосу и номер видно и в режиме «весь
файл». Дифф выделяется мышью, копирование помечается суффиксом
`[diff: путь]`.

**Откат** — с подтверждением на отдельном экране (Esc отменяет, файл не
тронут); шапка подтверждения прямо называет цель (см. «Лестница точек
отсчёта» выше), а у набора из одного файла ещё и держит его имя — тело
тогда без отдельной строки с именем. Тело — дерево блоков, без курсора и
выделения: блок на файл (имя со счётчиками, если файлов больше одного, цель
отката, предупреждения и сам дифф), между блоками пустая строка; `↑↓` и
`PgUp`/`PgDn` листают тело, когда оно не помещается на экран целиком, —
иначе подсказка прокрутки в футере не показывается. Клавиш перехода между
файлами (`n`/`p`) на этом экране нет — по дереву только прокручиваются.
`Enter` подтверждает весь набор и называет его объём прямо на себе —
`Enter откатить 1 файл`. Откат созданного агентом файла означает удаление
файла — подтверждение говорит это прямо, и созданного **командой** это тоже
касается: чтобы удалить файл, знать его прежнее содержимое не нужно.
Изменение файла **командой** теперь тоже можно откатить в доказуемых
случаях: если файл был чистым (без ваших несохранённых правок) до команды —
точная база берётся из последнего коммита в тех концах строк, что сейчас у
файла на диске (команда, поменявшая сами переводы строк, унесёт эту смену и
в базу); отдельно, перед каждой командой экран на всякий случай запоминает
содержимое файлов, уже известных ему, — если команда изменит такой файл,
откат будет доступен независимо от чистоты. Путь с настроенным в
`.gitattributes` фильтром, особой кодировкой рабочего дерева или
разворачиваемым `$Id$` (`filter`, `working-tree-encoding`, `ident`) точной
базы не получает вовсе — для него только счётная база, без отката. В
остальных случаях достоверного «до» по-прежнему нет, и такой файл уходит в
подтверждение собственным блоком с приглушённой причиной пропуска, а не
сводной строкой предупреждения над телом. У источника «ход» подтверждение
может показать предупреждение — если откат заденет ступень, возникшую после
начала хода (см. выше); это не запрет, а именно предупреждение, и стоит оно
в блоке своего файла. Во время живого прогона откат отклоняется: агент
пишет те же файлы. Если файл изменился, пока подтверждение было открыто
(например, вы поправили его в редакторе), или цель отката сдвинулась —
в другом окне сняли принятие или сделали коммит, — `Enter` не пишет ничего: экран
предупреждает и перечитывает список — откройте подтверждение заново, чтобы
увидеть то, что на диске сейчас. Путь, который с момента правки стал идти через
ссылку на другой каталог (или сам стал ссылкой), откат пропускает с причиной:
запись или удаление по нему ушли бы за пределы проекта. После отката агенту уходит техническое сообщение (EN) со
списками restored / deleted — «перечитайте эти файлы с диска».

**Большой набор — компактное подтверждение.** Если в подтверждении отката или
сброса больше 300 файлов, тела диффов не рисуются: тысячи блоков открывались
бы и прокручивались секундами. Первой строкой тела об этом сказано прямо, а
дальше каждый файл назван поимённо — набор не режется. Форма у отката и сброса
одна: строка файла несёт имя и цель (у отката — счётчики и стрелку `→ …`, у
сброса — «после сброса счёт пойдёт от …»), под ней с отступом — всё, что
полный вид говорит о файле, кроме самого диффа: предупреждения цветом
предупреждения, «превью недоступно», «отменять нечего», причина пропуска,
цена сброса. Дифф любого файла можно открыть на экране изменений.

**Принятие** (`a` / `Ctrl+A`) объявляет содержимое диска новой точкой
отсчёта. В git-репозитории следом идёт best-effort `git add` — отдельной
клавиши «только застейджить» на экране больше нет, стейджинг происходит
только как часть принятия. Плашка называет обе стороны: `✓ принято: <имя> —
новая точка отсчёта; файл добавлен в индекс git` (в обычной папке — без
упоминания индекса). Если в индекс заодно попали и ваши правки, сделанные
вне агента, плашка это тоже называет прямо. Принять можно и из источника
«ход» — база «сессии» сдвигается точно так же, но сам «ход» её не
показывает (его точка отсчёта всегда «начало хода»), поэтому плашка в этом
случае дополнительно называет источник, где сдвиг реально виден: `эффект
виден в «Сессии» — «Ход» по-прежнему считает от начала хода`. Отказ самого
git — предупреждение с причиной и подсказкой повторить `a` позже или выполнить
`git add` вручную; точка отсчёта при этом остаётся сдвинутой. Принять можно
файл в пределах лимита `max_diff_source_bytes` — файл больше лимита откажет
плашкой с причиной. Ни принятие, ни отмена принятия не сообщаются агенту —
вы не меняли файлы на диске, агенту нечего перечитывать.

Большой дифф открывается сразу: тело собирается по мере прокрутки, а место под
непоказанные ещё участки зарезервировано — полоса прокрутки честна, содержимое
не прыгает, `n` / `p` доводят до правки и в неразобранной части.

Данные для экрана пишутся **во всех режимах** работы агента (TUI, CLI, REST) —
тред, прогнанный из CLI, откроется в TUI со своими правками. UI есть только в
TUI. Снимки «до правки» лежат в `.gc/agent_edits` служебного каталога проекта
и самоигнорируются в git.

Лимиты — секция `diff_tui:` в конфиге (см. ниже).

## Настройки (`/settings`)

Правка конфига прямо из агента — без редактора и перезапуска. Семь секций:
**подключение** (адрес API-сервера и токен на одном экране), **модели** (реестр
моделей, уровни и привязки), **профили**, **MCP-серверы**, **голосовой ввод**,
**режимы работы**, **обновление**. Сохранение пишет в ваш `config.yml`; если в этот
момент идёт запуск, настройки применятся к следующему.

Значение вида `${ENV:GC_API_KEY}` экран показывает как **ссылку на переменную
окружения** — со статусом «подставилась» или «переменной нет» — и не превращает её в
литерал молча: если вы вписываете значение поверх ссылки, потребуется подтверждение.
На форму `${FILE:путь}` это **не** распространяется: экран её ссылкой не считает,
статус не показывает и перезапись подтверждением не защищает — правьте такие
значения в `config.yml` напрямую.

Сохранённый токен экран показывает маской. **`Ctrl+U`** на поле токена стирает его,
не уводя с экрана: маска уходит сразу, проба с этого момента идёт без токена, а из
`config.yml` он пропадёт при сохранении. Передумали — просто наберите новый, пометка
снимется сама. Клавиша работает везде, где показана маска, — в том числе поверх ссылки
`${ENV:...}`. Молчит она в двух случаях: сохранённого токена нет или выбран вариант
«без токена» — стирать нечего.

**Поля со списком** бывают двух видов, и ведут себя они по-разному — различие
намеренное.

**Список моделей** — это содержание поля: другого источника значения нет, мимо списка
идти некуда. Поэтому он раскрыт всегда и не сворачивается, а под рамкой стоит блок
статуса («1 модель», «не удалось получить список»).

**Список провайдеров** под адресом API-сервера — помощник: адрес можно вписать и
руками. Поэтому он раскрыт, только пока значение складывается **и** есть из чего
выбирать:

- курсор пришёл на пустое поле — список раскрывается сам; пришёл на заполненное — нет:
  стрелки водят по форме, а под полем стоит постоянная строка «`Alt+↓` — показать
  список»;
- печать — фильтр и одновременно ввод своего адреса. Как только набранное перестаёт
  совпадать хоть с одной строкой, список сворачивается, а строка под полем сообщает
  «в списке такого нет» и называет, чем его вернуть.

Общие клавиши обоих видов:

- **`Alt+↓`** (и `Ctrl+↓`) — «дай мне список»: свёрнутый показывает, список с сервера
  перечитывает — он и так открыт, прятаться ему некуда;
- **`Ctrl+Space`** — проверить связь. Списка эта клавиша не касается и работает там,
  где проба вообще есть: «Подключение», форма записи реестра в «Моделях» и облачная
  панель «Голосового ввода»;
- **`Esc`** — свернуть список, **`Enter`** — подставить выбранную строку.

Одна клавиша — одна роль: что произойдёт, не зависит от того, раскрыт список или нет.

Клавиши секции MCP: `Space` — подключить/отключить, `Enter` — установить,
`Ctrl+U` — обновить версию, `Del` — удалить пакет.

Секция **Модели** — реестр моделей, уровни и привязки потребителей одним экраном
(см. [Конфигурация](configuration.md#профили-и-уровни-моделей)); прежняя секция
«модель» вошла в неё. В меню видно `N в реестре · default <алиас>` (хвост — когда слот
`default` задан), а в легаси-режиме (реестра нет) — имя одной модели, как раньше.
Строки сверху вниз, группы разделены чертой: записи реестра (алиас, провайдерский id
и, у записи, на которую смотрят уровни, — хвост со списком ВСЕХ этих уровней:
`← default`, `← light, max`) со строкой-действием `+ добавить модель…` в конце блока,
три **уровня**, блок **привязок** и последней — **резервная модель**
(`agent.model` с хвостом «не работает при живом реестре»). Строка эта — предупреждение
тому, у кого ключ остался в конфиге: не задан — её не рисуют вовсе, и у профиля её тоже
нет (`agent.model` живёт в `config.yml`). Что секция умеет:

- `Enter` на записи — открыть её форму, `n` — добавить запись, `Del` — удалить
  (подтверждение на месте: баннер называет ссылающиеся слоты и привязки — они снимутся
  вместе с записью, — а на последней записи предупреждает, что реестр станет пустым и
  уровни выключатся);
- в форме записи — адрес, токен, провайдерский id и алиас (порядок полей сверху вниз).
  Алиас правится и у существующей записи: переименование переносит за собой слоты и
  привязки, поэтому руками в `models:` его лучше не трогать — ручная правка ссылки не
  тащит. `Ctrl+Space` — проверить
  связь, `Alt+↓` — подобрать список моделей с эндпоинта: клавиши разные, проба ничего
  не подбирает. Адрес и токен — **пара**: их задают вместе или наследуют вместе,
  половины не бывает (свой адрес без токена и свой токен без адреса форма не сохранит,
  а назовёт, чего не хватает). Строка над полями говорит, откуда пара взята: «Адрес и
  токен: наследуются из раздела «Подключение»» или «Адрес и токен: свои»; если пара задана
  секцией `backend` самой записи — «свои — заданы секцией backend, правятся в файле»
  (этих ключей форма не касается). Пустые поля и значат наследование, а их подсказки
  называют унаследованное значение (токен — маской). `Ctrl+U — вернуть наследование`
  работает на обоих полях пары и возвращает её целиком; названа она у токена подписью
  поля, а на адресе — футером (подписи с клавишей там нет), и дважды в одном кадре не
  повторяется; тот же
  вход — первый пункт списка адресов, `раздел «Подключение» · наследовать`. Галка
  «без авторизации» доступна только при своей паре — при унаследованной строка говорит, что
  токен приходит из «Подключения». Ключи, которых в форме нет (`pricing`, `backend`),
  сохранение не теряет — запись сливается, а не переписывается;
- `Enter` на строке уровня — выбрать модель, `Enter` на строке привязки — выбрать
  уровень или модель. Первая строка списка **снимает** значение: уровень вернётся к
  фоллбэку, потребитель уйдёт на активную модель;
- реестра ещё нет — секция показывает обычный редактор одной модели и объясняет, что
  уровни выключены; завести первую запись реестра оттуда — `Alt+N` (обычная `n` там
  печатается в поле).

Записывается каждое действие сразу, а не общим «сохранить». Проверок перед записью две.
Схему и форму спрашивают у **того файла, который правится** — профиль частичен, и своей
схеме он обязан соответствовать сам. А вот ссылочную целостность (каждый слот и каждая
привязка находят свою запись) считают по **стеку, который загрузит следующий старт**:
база → managed → project → активный профиль. Поэтому снять из `config.yml` модель, на
которую смотрит слот активного профиля, экран не даст, а раскладка «записи в базе, слоты
в профиле» — законна. Неактивные профили никого не держат: их битую ссылку ловит
уведомление при активации. Не сложилось — файл остаётся нетронутым, а экран называет
причину.

Секция **Профили** — витрина файлов профилей из обоих корней поиска (см.
[Конфигурация](configuration.md#профили-и-уровни-моделей)). Уровень модели по
умолчанию правится не здесь, а в секции «Режимы работы» — он глобальный ключ
конфига и к профилям отношения не имеет. Что умеет секция:

- `Space` на строке профиля — **активировать** его (записать указатель `profile:` в
  конфиг), `Space` на строке «без профиля» — деактивировать;
- `Enter` на строке профиля — **открыть** его: тот же редактор, что и секция «Модели»,
  но над файлом профиля. Список показан **действующий**: свои записи профиля плюс тень
  основного конфига, с колонкой происхождения — иначе не видно, что уже досталось по
  наследству. `Enter` и `Del` на унаследованной строке отвечают отказом и называют файл,
  где её правят. Над списком перечислены прочие секции, которые профиль перекрывает.
  `v` — открыть сам файл профиля на просмотр (клавиша есть, пока включён
  `tui.file_view.enabled`). `Esc` — назад к списку;
- `n` — создать профиль: имя спрашивается строкой ввода под списком, файл ложится в
  **базовый** корень (проектный `.gc/profiles/` остаётся ручной территорией) и сразу
  открывается в редакторе. Та же дверь есть строкой-действием `+ добавить профиль…`
  (последняя в списке, `Enter` на ней = `n`); профилей ещё нет — курсор стартует
  на ней. `r` — переименовать (указатель на активный профиль
  переезжает следом), `Del` — удалить (файл уезжает в
  `backups/<файл>.bak-<ГГГГММДД-ЧЧММСС>` рядом с собой, уведомление называет путь).

Профилей ещё нет — секция объясняет, что такое профиль, и показывает одно действие:
строку `+ добавить профиль…`, на которой курсор стоит сразу. Полный путь будущего файла
называет подсказка под списком — она считает его от фактического корня профилей, поэтому
верна и при своём `GC_HOME`, и при запуске с `--config`. Формат профиля описан в
[Конфигурации](configuration.md) и в `demo_profile.yml` — в экран он не дублируется.

Куда именно пишется указатель, экран говорит прямо в подсказке (`запись: <путь>`):
проектный профиль — в проектный `.gc/config.yml`, глобальный — в базовый `config.yml`
(но тоже в проектный, если тот уже задаёт `profile:` сам, иначе запись была бы
бессмысленной). В самой строке — имя, источник (проектный / глобальный), отметка
`● активен` и состав слотов профиля; в подсказке под списком — путь выбранного файла,
перечень его секций-оверлеев и, если у имени есть тёзка в другом корне, путь
проигравшего файла. В отличие от палитры,
эта секция меняет **глобальное** значение, а не текущую сессию; сессионный вход к тому
же — `/profiles`.

Секция **Режимы работы** — те же переключатели, что `/gate` и `/answers` в
командной палитре (см. «Переключатели в палитре» выше), но меняют не сессию, а
**глобальный дефолт** в `config.yml`: превью в меню — пары `label: value` через
` · ` в порядке тогглов, на узком терминале усекается целыми парами (пара не
режется посередине). Подэкран — по строке на тоггл, тот же вид слайдера (label +
трек + значение), ←/→/Enter записывают выбор в `config.yml` МГНОВЕННО, Esc —
назад в меню. Если текущая сессия перекрывает глобальный дефолт (переключали в
палитре), в конце той же строки тускло видно «· в текущей сессии: Y» — сама
строка по-прежнему показывает и правит глобал, Y — то, что реально в силе.

Под чертой, отдельным блоком, — строка `level · уровень модели по умолчанию`:
тот же слайдер и те же клавиши. Подсказка под ней называет не абстрактный
уровень, а **модель, которая за ним стоит** в действующем реестре, и роль уровня.
Слово «по умолчанию» отличает эту строку от `/level` в палитре: здесь правится
файл, там — только текущая сессия.

Куда уходит запись, плашка результата говорит полным путём. Правило одно для всей
секции: значение пишется в тот файл, который этот ключ **уже задаёт**. Обычно это
базовый `config.yml`, но если ключ задан проектным `.gc/config.yml` — запись идёт
туда, иначе проектный слой всё равно перекрыл бы её и ручка бы «не сработала».
Проектный файл при этом не трогается ради ключей, о которых он молчит: он часто
приезжает с клоном репозитория, и класть туда личную настройку незачем.

Перекрыть значение может и то, куда секция не пишет вовсе, — файл активного
профиля или machine-managed `~/.gc/config.local.yml`. Тогда вместо плашки об
успехе экран говорит, что записано и что действует на самом деле, и называет
перекрывший слой поимённо («значение перекрыто профилем work (глобальным)»).
Отказ записи оставляет файл нетронутым: правка либо применяется целиком, либо
не применяется вовсе.

Секция **Обновление** показывает вердикт проверки версии и ставит новую версию
(`update.check`, `update.extra_args` — см. [Конфигурация](configuration.md)).
Тот же экран открывается сам при первом запуске (мастер настройки) и после
обновления агента (что нового + что осталось обновить).

## Сессии

`Ctrl+S` / `F2` или `/sessions` — список сессий текущего проекта. Карточка:
заголовок (своя метка, иначе авто-имя из `last_actual`), время изменения,
git-ветка, число сообщений, статус, id; при включённом `pricing` — стоимость
сессии (сумма меньше минимальной денежной единицы показывается как `<0.01`; та же функция
форматирования, что и в футере, — поэтому на карточке могут стоять те же
знаки `+`/`~`/`?`, см. [usage_pricing.md](usage_pricing.md)).

- поиск по id или тексту — поле внизу;
- `↑↓ / Home / End` — выбор, `PgUp / PgDn` — страницы (по 25);
- `Enter` — открыть и продолжить;
- `Ctrl+P` — превью треда без открытия (`Enter` из превью — продолжить);
- `Ctrl+R` — переименовать (пустое имя → авто-имя из `last_actual`);
- `Ctrl+B` — фильтр по текущей git-ветке (только в git-проекте);
- `Del` — удалить с подтверждением;
- `Ctrl+D` — массовое удаление по критерию (с подтверждением);
- `Esc` — назад.

`gc-ua` и `gc-cli` используют общий namespace тредов (`system="cli"`, один
`threads_data_path`): задачу, начатую в `gc-cli -t ...`, можно продолжить в TUI
и наоборот.

## Подтверждение опасных операций (ConfirmBanner)

Если операция затрагивает защищённые пути (например `.gc/`), агент не продолжает
молча — над полем ввода появляется баннер с описанием операции (Tool / Path / Command)
и тремя вариантами выбора:

| Клавиша | Действие |
|---|---|
| `Y` | Разрешить (однократно) |
| `S` | Разрешить в текущей сессии — не спрашивать снова |
| `N` | Нет — отклонить |

`↑↓` — сменить выбор, `Enter` — подтвердить. При выборе «Разрешить в сессии» агент
запоминает решение и не переспрашивает для той же операции до конца сеанса.

## Когда агент задаёт вопрос (ask_human)

Над полем ввода появляется баннер с текстом вопроса, плейсхолдер меняется на
`ваш ответ агенту…`, в шапке — статус `[asking]`. Напечатайте ответ и нажмите
Enter — агент продолжит. Esc при пустом поле останавливает тред (агент не получает
ответа и не зацикливается на вопросе); продолжить можно следующим сообщением.

## Чек-лист задачи (session_todo)

Многошаговую задачу агент планирует сам и ведёт список по ходу работы — в трейсе
это отдельный блок:

```
session_todo   чек-лист 2/4
  ✓ И̶з̶у̶ч̶и̶т̶ь̶ ̶п̶р̶о̶е̶к̶т̶
  → Написать тесты
  ○ Прогнать приёмку
```

- `K/M` — сделано из всего; `✓` зачёркнутым — готово, `→` — в работе, `○` — впереди;
- каждое обновление — новый блок, поэтому видно, как менялся план;
- клик выделяет блок целиком, Ctrl+клик открывает payload вызова;
- у субагента свой чек-лист внутри его блока — план оркестратора он не затирает;
- список переживает сжатие контекста и границы ходов.

Если список долго не обновлялся, харнес напоминает агенту; частота — ключ
`todo.reminder_steps` (по умолчанию 10 шагов, `0` — выключить).

## Суммаризация в трейсе

Когда история треда сжимается (режим `chat_completions`):

- во время сжатия индикатор показывает `⠋ сжимаю контекст…`;
- в трейсе остаётся маркер `▸ ──── контекст сжат #K · N→1 · 12.3k→3.1k симв ────`
  (стрелка `▸`/`▾`, порядковый номер, число сообщений до/после, объём символов до/после);
- клик или Enter по маркеру разворачивает `▾` / сворачивает `▸` блок `Контекст сохранён:`
  с текстом сводки; при раскрытии трейс автоматически прокручивается к телу.

## Конфигурация TUI

Параметры в секции `tui:` файла `config.yml`:

| Ключ | Значения | По умолчанию | Что делает |
|---|---|---|---|
| `tui.stream_display` | `minimal` / `answer` / `answer_reasoning` | `minimal` | Что показывать во время стрима (`chat_completions + backend.stream: true`): `minimal` — только индикатор + счётчик токенов; `answer` — прогрессивный ответ, дорастающий до финала; `answer_reasoning` — то же + однострочный «глазок» рассуждения. |
| `tui.finish_gate_mode` | `on` / `smart` / `off` | `smart` | Судья полноты ответа (intent_guard) на завершении хода: `on` — проверяет всегда, закрывает ли финальный ответ интент пользователя, при несоответствии — reject и повторный прогон; `smart` — проверяет только если за ход был хотя бы один вызов инструмента; `off` — гейт выключен. Переключается на лету командой `/gate` в палитре (или пресетом `/rigor`). |
| `tui.text_answer_mode` | `deny` / `judge` / `allow` | `judge` | Как поступать с текстовым ответом без tool-вызова (адаптивный turn-contract): `deny` — всегда bounce, как в CLI; `judge` — судья intent_guard решает, закрывает ли текст интент пользователя; `allow` — всегда принять текст. |
| `tui.bang_shell.enabled` | `true` / `false` | `true` | Разрешить префикс `!` (локальный shell). При `false` — отказ в трейсе, не в агента. |
| `tui.bang_shell.timeout_sec` | число / `null` | `null` | Авто-kill через N секунд; `null` / omit / `0` — без лимита (отмена вручную Esc/Ctrl+C). |
| `tui.bang_shell.max_output_bytes` | число | `32768` | Порог truncate вывода (что раньше — байты или строки). |
| `tui.bang_shell.max_output_lines` | число | `200` | Порог truncate вывода по строкам. |
| `tui.file_view.enabled` | `true` / `false` | `true` | Разрешить `/view` — и вместе с ним клавишу `v` (просмотр файла профиля в секции «Профили»): при `false` она просто не обещается. У `/view` при `false` — сообщение на экране viewer, не в агента. |
| `tui.file_view.max_file_bytes` | число | `67108864` | Максимальный размер файла для просмотра (64 MiB). |
| `tui.file_view.page_lines` | число / `null` | `null` | `null` — авто по высоте тела экрана; число — фиксированный шаг PgUp/PgDn (1…200). |

Параметр `backend.stream` (`true` / `false`, по умолчанию `true`) — мастер-переключатель SSE-стрима.
При `false` стриминг, живой счётчик токенов и прогрессивный ответ недоступны.

Секция `diff_tui:` — запись правок агента и их показ в TUI (не параметры
fs-тулов `return_diff`):

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `diff_tui.snapshots_max_files` | `500` | Лимит снимков «до правки» в `.gc/agent_edits` (LRU; треды с живым журналом не вытесняются) |
| `diff_tui.max_diff_chars` | `100000` | Усечение больших диффов (`0` — без лимита) |
| `diff_tui.hunk_context_lines` | `3` | Строк контекста в хэнках журнальных диффов |
| `diff_tui.max_diff_source_bytes` | `2000000` | Порог размера файла: свыше — дифф не считается, снимок не снимается |
| `diff_tui.shell_tracking` | `true` | Трекинг правок, сделанных shell-командами |
| `diff_tui.trace_inline_max_lines` | `24` | Строк диффа в ленте до свёртки |
| `diff_tui.replay_expanded_turns` | `20` | Сколько последних ходов разворачивать при открытии треда (`0` — все) |
| `diff_tui.turn_summary_in_status` | `true` | Сводка правок в строке-итоге хода |

## Внешний вид

- **Логотип**: truecolor-градиент (gold-рампа) — автоматически включается на терминалах
  с поддержкой 24-bit цвета; на остальных — базовый `$brand`-цвет.
- **Заголовок окна**: `✦ GigaCode ▸ <задача>` (OSC-0 escape) — вкладка / заголовок
  терминала отражает текущий статус и первые 50 символов задачи.
- **Длительность**: человекочитаемый формат — `Nс` / `Nм Mс` / `Nч Mм`
  (например «2м 5с», а не «125с»).

## MCP

На старте `gc-ua` подключение MCP-серверов идёт в фоне; в трейсе виден живой блок
`подключаю MCP:` со статусом каждого сервера (⏳ → ✓/✗), который затем сворачивается
в итог: `✓ MCP: все подключены` (или `⚠ MCP: <имена> недоступны — подробности
в /mcp`) и `✓ готов к работе`.

`/mcp` — экран MCP-серверов: статус каждого и список его тулов
(`Enter` раскрыть, `↑↓` серверы, `Esc` назад).
