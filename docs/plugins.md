# Плагины (песочница, экспериментально)

Плагины (экспериментально): каталоги со skills, хуками, MCP-серверами, командами
и субагентами. Раскладка как у Claude Code, поэтому готовые плагины оттуда
подключаются без переделки. Поддержан и формат Agent Plugins (agent-plugins.org):
`plugin.json` в корне, `skills/`, `mcp.json`. Без настройки ничего не меняется: списки плагинов по
умолчанию пусты.

## Как включить

В конфиге (тот же `config.yml`, что у `gc-cli`) добавить секцию:

```yaml
plugins:
  paths:
    - /абсолютный/путь/к/superpowers
  hook_timeout_sec: 30
```

Ключ `plugins.use_installed` (по умолчанию `true`) решает, подключать ли плагины,
установленные `gc-plugin install`; при `false` работают только `paths` и `sources`.
Бенчи Harbor выставляют `false`, чтобы прогон не зависел от плагинов на машине.

Автопоиска каталогов нет: плагин работает, только если указан явно (`paths`,
`sources`) или установлен командой `gc-plugin install` (см. ниже). Убрать плагин
значит убрать строку из конфига или выключить его командой `gc-plugin disable`.

## Что такое плагин

Каталог со следующим содержимым (раскладка как у Claude Code, всё необязательно):

```
my-plugin/
  .claude-plugin/plugin.json   # имя и версия (или plugin.json в корне)
  skills/<id>/SKILL.md         # skills, видны агенту как системные
  commands/<имя>.md            # команды: готовый запрос под коротким именем
  agents/<имя>.md              # субагенты: роль и набор инструментов
  hooks/hooks.json             # хуки
  .mcp.json                    # MCP-серверы (или mcp.json без точки; .mcp.json главнее)
```

`hooks.json`:

```json
{
  "hooks": {
    "SessionStart": [{ "matcher": "startup", "hooks": [{ "type": "command", "command": "python3 \"${CLAUDE_PLUGIN_ROOT}/hooks/x.py\"" }] }],
    "PreToolUse":   [{ "matcher": "exec_command", "hooks": [{ "type": "command", "command": "..." }] }],
    "PostToolUse":  [{ "matcher": "*", "hooks": [{ "type": "command", "command": "..." }] }]
  }
}
```

## События

| Событие | Когда | Что может хук |
|---|---|---|
| `SessionStart` | один раз на тред перед первым запросом к модели (`chat_completions`), источник `startup`; не в субагентах | вернуть `additionalContext`: он добавится технической user-репликой |
| `PreToolUse` | перед исполнением инструмента | запретить вызов, подменить аргументы (`updatedInput`) |
| `PostToolUse` | после исполнения | только наблюдение (аудит, логи) |
| `PostToolUseFailure` | вместо `PostToolUse`, если вывод инструмента `ok: false` | только наблюдение |
| `UserPromptSubmit` | на сообщении пользователя (`chat_completions`, не в субагентах); в stdin `prompt` | `additionalContext` добавится технической репликой; `block` превращается в реплику с причиной (запрос уже в истории) |
| `Stop` | перед завершением хода (`chat_completions`, не в субагентах); в stdin `stop_hook_active`, `last_assistant_message` | код 2 или `decision: block` не пускает к завершению, причина уходит модели; не больше 3 продолжений подряд |

`matcher`: `*` или пустая строка подходят всегда, иначе регулярное выражение,
которое должно совпасть целиком. Для `SessionStart` сверяется источник старта,
для событий инструментов имя инструмента: подходит и имя агента (`exec_command`,
`fs_write_file`), и имя Claude Code (`Bash`, `Edit`).

## Контракт хука

- **Вход:** JSON на stdin: `hook_event_name`, `session_id`, `cwd`, для инструментов
  `tool_name` (имя Claude Code, если оно есть, иначе имя агента) и `tool_input`
  (всегда в схеме аргументов агента, не Claude Code); для `PostToolUse` ещё
  `tool_response`.
- **Окружение:** всегда заданы `GC_PLUGIN_ROOT` и `CLAUDE_PLUGIN_ROOT` (каталог
  плагина) и `GC_PROJECT_DIR`.
- **Выход:** код 0 и необязательный JSON. Код 2 запрещает вызов, причина берётся из
  stderr. Понимаются `decision: "deny"` и `reason`, `additionalContext` верхнего
  уровня или в `hookSpecificOutput`, `updatedInput`.
- **Сбои:** другой код выхода или таймаут не останавливают агента, в лог уходит
  предупреждение (fail-open).
- Модель получает отказ как результат инструмента:
  `{"ok": false, "error": "blocked_by_plugin", "plugin": "...", "message": "..."}`.

## Команды плагина (`commands/`)

Команда это файл `commands/<имя>.md` с необязательной YAML-шапкой
(`description`, `argument-hint`, `allowed-tools`) и текстом запроса. В тексте
`$ARGUMENTS` заменяется аргументами команды, `$1`..`$9` отдельными словами
аргументов.

```markdown
---
description: Проверить файл на ошибки
argument-hint: <файл>
---
Прочитай файл $1 и найди в нём ошибки.
```

Как вызвать:

- **`gc-cli` (проверено), сервер и чат (тот же цикл, не проверялись):** написать `/плагин:команда аргументы` (подойдёт и
  короткое `/команда`, если такое имя у одного плагина). Агент добавит к запросу
  техническое сообщение с текстом команды, где аргументы уже подставлены.
- **TUI** (не проверялся): собственные команды TUI не расширяются, а `/что-то` вне их списка даёт
  ошибку «неизвестная команда». Используйте `/skill плагин:команда аргументы`:
  каждая команда плагина доступна как skill с id `плагин:команда`.
- Модель тоже видит такие skills и может загрузить их сама.

Что не переносится: `allowed-tools` и `model` из шапки читаются, но не
применяются, а вложенные папки `commands/` не обходятся.

## Субагенты плагина (`agents/`)

Файл `agents/<имя>.md` (шапка YAML и текст роли) становится кастомным субагентом
агента и подчиняется тем же правилам, что и папка `agent.subagents_dir`:
нужны `agent.use_local_subagents` и `backend.api_mode: chat_completions`,
действуют лимит `subagents_max_count` и список имён в `use_local_subagents`.
Встроенный субагент и определение из `subagents_dir` с тем же именем побеждают.

Перевод формата Claude Code:

| В файле плагина | В агенте |
|---|---|
| `name` (любое) | инструмент `subagent_<плагин>_<имя>`: нижний регистр, всё лишнее становится `_`, не длиннее 64 знаков |
| `description` | описание субагента (обрезается до 1024 знаков; если пусто, подставляется «Субагент плагина …») |
| `tools: Read, Grep, Bash` | `fs_read_file`, `fs_find_in_files`, `exec_command` |
| нет `tools` | доступны все инструменты |
| `model`, `color` и прочие поля | не переносятся |
| текст файла | роль субагента |

Соответствие инструментов: `Read` в `fs_read_file`, `Write` в `fs_write_file`,
`Edit` и `MultiEdit` в `fs_apply_file_edits`, `Grep` в `fs_find_in_files`,
`Glob` в `fs_find_files_by_name`, `LS` в `fs_list_files`, `Bash` в
`exec_command`, `WebFetch` в `exec_fetch_url`, `TodoWrite` в `session_todo`.
Имена в формате агента (`fs_read_file`) принимаются как есть. Неизвестные
(`WebSearch`, `Task`, `mcp__*`) отбрасываются с предупреждением. Если из
непустого списка не осталось ни одного инструмента, субагент пропускается:
иначе он получил бы больше прав, чем задумал автор.

## Границы

- Хуки идут ДО встроенной защиты (`security`, `write_guard`), поэтому плагин может
  только ужесточить, но не обойти её.
- Хуки это внешние процессы с правами пользователя. Подключайте только то, чему
  доверяете.
- В durable-режиме (Temporal) хуки отключены: запуск процесса внутри workflow
  нарушил бы детерминизм. Нужен порт рантайма.
- `SessionStart` срабатывает один раз на тред, если хук вернул контекст: факт
  запуска определяется по техническому сообщению в истории, поэтому при
  возобновлении треда повторно не идёт. Без вывода (или при сбое) хук идёт раз на
  ход. Поведение при `/clear` не проверялось.
- Встроенная модерация команд работает как раньше: в `gc-cli` без человека она
  отклоняет часть команд сама, и плагин на это не влияет.
- Не проверялось в TUI, ACP и `gc-server`; проверено в `gc-cli` с мок-моделью.
- Хуки на события, которых здесь нет (например `SubagentStop`, `PreCompact`),
  пропускаются: плагин работает без них.
- Матчер с именем Claude Code (`Bash`, `Edit`) срабатывает на соответствующий
  инструмент агента, но `tool_input` приходит в схеме агента (`command`, `path`...),
  а не Claude Code: хук, читающий `file_path`, его не найдёт.
- Хук Claude Code, возвращающий `updatedInput` в схеме Claude Code (`file_path`,
  `old_string`...), сломает аргументы инструмента агента: `tool_input` и
  `updatedInput` живут в схеме агента.
- Пути к компонентам в `plugin.json` (`skills`, `commands`, `agents`, `hooks`,
  `mcpServers`) не учитываются: читаются только стандартные каталоги. Например,
  `mattpocock/skills` ставится с 0 skills.

## Пример

- Реальный плагин [superpowers](https://github.com/obra/superpowers) (15 skills,
  вводный текст при старте) работает без правок: хук получает `CLAUDE_PLUGIN_ROOT`
  и отвечает в формате, который агент принимает.

## Как отключить и удалить

- Плагин из конфига: убрать строку из `plugins.paths` или `plugins.sources`.
- Установленный командой: `gc-plugin disable <имя>` (файлы остаются) или
  `gc-plugin uninstall <имя>`.
- Весь код песочницы: вернуть изменённые файлы (`git checkout -- <файлы>`) и
  удалить новые: `packages/core/src/gc_core/plugins/`,
  `packages/core/src/gc_core/config_modules/plugins.py`,
  `packages/core/tests/plugins/`, этот документ.

## MCP из плагина (`.mcp.json`)

Файл `.mcp.json` в корне плагина читается как у Claude Code: `{"mcpServers": {имя: {...}}}`
или сразу `{имя: {...}}`. Поддержаны `stdio` (`command`, `args`, `env`, `cwd`) и `http`/`sse`
(`url`, `headers`); `${CLAUDE_PLUGIN_ROOT}` заменяется путём плагина. Серверы попадают в
`mcp.servers` под именем `<плагин>_<имя>`; одноимённый сервер пользователя не перезаписывается.
Раскладка Agent Plugins `mcp.json` (без точки) читается тоже; если есть оба файла, берётся `.mcp.json`.
Битый сервер пропускается с предупреждением (значения из файла в лог не пишутся), остальные грузятся.

## Плагин из git (`plugins.sources`)

```yaml
plugins:
  sources:
    - git: obra/superpowers        # owner/repo (GitHub) или полный URL
      ref: main                    # ветка, тег или хеш коммита (необязательно)
      subdir: null                 # каталог плагина в репозитории (необязательно)
  paths: []                        # локальные каталоги по-прежнему можно
```

Агент клонирует репозиторий в `<gc_cache>/plugins/<имя>-<хеш>` один раз; дальше работает
из кэша без сети. Тег или хеш в `ref` фиксируют версию. Для ветки обновление явное:

```bash
python -m gc_core.plugins.sources update
```

Клон делается только при загрузке настроек (`load_settings`) или командой `gc-plugin`;
цикл агента берёт плагин из кэша и один раз предупреждает, если источник ещё не склонирован.
Сбой клона не останавливает агента: плагин пропускается, в лог идёт предупреждение.

## Установка в постоянное хранилище (`gc-plugin`)

Как у OpenHands: плагин ставится один раз и дальше работает без правки конфига.

```bash
gc-plugin install obra/superpowers            # owner/repo, URL или локальный путь
gc-plugin install obra/superpowers --ref v5.0.0   # зафиксировать версию (тег или хеш)
gc-plugin list                                # on/off, имя, версия, источник, коммит
gc-plugin disable superpowers                 # файлы остаются, плагин не грузится
gc-plugin enable superpowers
gc-plugin update superpowers                  # переустановить из источника (для ветки)
gc-plugin uninstall superpowers
```

Хранилище: `<gc_data>/plugins/installed/<имя>/` (на macOS/Linux `~/.local/share/gc/...`),
метаданные в `.installed.json`. Одноимённый плагин, заданный и в конфиге, и в хранилище,
загружается один раз (первый из списка). Без установленных плагинов поведение не меняется.
