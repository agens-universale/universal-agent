# Редизайн хрома TUI: мета-строка, зарезервированный спиннер, адаптивный путь

Дата: 2026-06-24
Статус: дизайн согласован (визуальный брейншторм), ждёт вычитки → план

## Проблема / цель

Сейчас вся служебная информация набита в хедер-слева одной строкой
(`Сессия: <id>  [status]  модель: <model> · chat  ·  контекст <bar> N%`), индикатор
активности («думаю…») монтируется/уничтожается внутри трейса и сдвигает контент, а
команды и транзиентные подсказки делят слот footer-left. Цель — переразложить хром
оптимально (по мотивам Hermes): отдельная мета-строка у поля ввода, всегда
зарезервированная строка активности, разгруженные хедер/футер, адаптивный путь.

Изменения **только презентационные** (раскладка/цвета/тексты). Логика суммаризации,
прогона, статусов, ask_human, confirm-баннеров — не трогается.

## Итоговая раскладка (сверху вниз)

```
┌ Сессия: a9b25aa8                          D:\dev\PycharmProjects\ai\ReAct-Agent ┐  ← ХЕДЕР (h2)
│ |- read_file(…) → 96 строк [ok]                                                │
│ • Полный анализ проекта завершён…                                             │  ← ТРЕЙС (scroll)
│ ▸ контекст сжат #1 · 79.8k→1.9k символ                                         │
│ ✓ Выполнил за 2м 38с                                                          │  ← СПИННЕР (низ трейса)
├───────────────────────────────────────────────────────────────────────────────┤
│ MiniMax-M2.7 · контекст ▓░░░░░░░ 8%                              [completed]   │  ← МЕТА (над вводом)
├───────────────────────────────────────────────────────────────────────────────┤
│ > опишите задачу или /команда                                                 │  ← ВВОД
├───────────────────────────────────────────────────────────────────────────────┤
│ /sessions /help /config /mcp                                            gc-ua │  ← ФУТЕР (h2: текст
│                                                                               │     сверху, пустая снизу)
└───────────────────────────────────────────────────────────────────────────────┘
```

Порядок снизу трейса: **спиннер (низ трейса) → мета → ввод → футер** (мета НАД вводом).

Разделители-линии между полосами: **хедер │ трейс(+спиннер) │ мета │ ввод │ футер**.
Между контентом трейса и спиннером линии НЕТ (спиннер — часть трейса). Цвет линий — в
тон существующих хедер/футер-разделителей (deep-dim; при ощущении тяжести — чуть
тусклее, тюнится в реализации).

## Полосы по отдельности

### 1. Хедер (height 2, bg #161A23, deep-dim, border-bottom)
- **Слева:**
  - сессия активна → `Сессия: <id8>` (deep-dim; `<id8>` = первые 8 символов task_id);
  - свежий экран (нет активной задачи) → `Добро пожаловать в GigaCode` (всё deep-dim, без
    акцента/глифа).
- **Справа:** путь cwd, **адаптивно усекаемый** (см. §Адаптивный путь), deep-dim.
- Из хедера УБИРАЮТСЯ: статус-бейдж и блок «модель: … · chat · контекст …» (уезжают в
  мету), а также текст `F1 help` (клавиша F1 остаётся рабочей; `/help` есть в командах).
  `gc-ua` уезжает в футер-право.

### 2. Трейс + зарезервированная строка спиннера (VerticalScroll, 1fr)
- Спиннер-строка — **последняя строка трейса** (тот же фон, без линии над ней), как сейчас
  thinking-indicator, но **всегда присутствует и всегда что-то показывает**; контент
  накапливается ВЫШЕ неё и никогда её не вытесняет.
- Состояния (как сейчас в `ThinkingIndicator`, цвета без изменений, кроме «готово»):
  - running → `▸ думаю… (Nс[ · ↓ N токенов][ · размышление/обдумал за Nс])` — анимированный
    глиф + ротация фраз, цвет RUN_COLOR (amber);
  - compressing → `◂ сжимаю контекст… (Nс)` amber;
  - validating → `✓ завершаю…` deep-dim;
  - processing → `· сверяюсь…` deep-dim (дыхание точкой);
  - **done (НОВОЕ) → `✓ Выполнил за <duration>` deep-dim** — серым, как «завершаю» (НЕ
    accent). Держится до старта следующего хода.
- Свежий экран (хода ещё не было) — спиннер-строки НЕТ вовсе; зарезервированное место
  появляется с первого хода и далее персистентно.
- Поведенческое следствие: индикатор больше не уничтожается по завершении хода, а
  переключается в `done` и живёт до следующего user-send. (Текущий falling-edge
  `tui.status` остаётся как есть — это про бейдж, не про текст спиннера.)

### 3. Мета-строка (НАД вводом, bg #0E1119, border-bottom)
- **Слева:** `<model> · <контекст-сегмент>`:
  - имя модели — цвет **контента** `$ink #ebe9e6` (как `.line-agent`); без ярлыка «модель:»
    и без тега бэкенда «chat/resp»;
  - контекст-сегмент — РОВНО текущий `render_context_meter`: текст `контекст <bar> N%`,
    цвет по порогам (OK<60 green, RUN ≤90 amber, WARN>90); слово «контекст», бар и цвет НЕ
    меняем, только переносим сюда.
- **Справа (у правого края):** `[status]`-бейдж, цвет `status_badge_color` (running amber,
  asking teal, completed green, stopped dim, failed err). Свежий экран → `[—]` deep-dim,
  контекст `░░░░░░░░ 0%`.

### 4. Ввод (border-bottom)
- `> ` (prompt, `$accent` teal) + `CommandTextArea`. Плейсхолдер: «опишите задачу или
  /команда»; в режиме ask_human → «ваш ответ агенту…» (как сейчас).

### 5. Футер (height 2, bg #161A23; текст в ВЕРХНЕЙ строке, нижняя пустая)
- Высота 2 строки: команды/gc-ua в верхней строке, нижняя пустая — чтобы поле ввода не
  липло к низу терминала.
- **Слева:** команды — покой `/sessions /help /config /mcp`; прогон
  `/stop /help /config /mcp` (в прогоне `/sessions`→`/stop`); `$dim`.
- **Справа:** `gc-ua`, deep-dim.

## Транзиентные подсказки (без изменений по месту — footer-left)
Подсказки остаются в слоте **footer-left** (как сейчас), временно подменяя команды; серым
(`$dim`, без акцента). Спиннер-строку и мету НЕ трогают.
- `Esc ещё раз, чтобы очистить` (2с) — 1-й Esc при тексте в поле;
- `Esc ещё раз, чтобы остановить` (2с) — 1-й Esc в прогоне;
- `вставьте ещё раз, чтобы развернуть` (5с) — свёрнутая в плашку вставка;
- ask_human → footer-left = `[Enter] ответить · [Esc] /stop` (как сейчас); статус-бейдж в
  мете = `[asking]` (teal); спиннер-строка в этот момент пуста (агент ждёт).
- Баннеры `[Y]/[N]` (выход / прерывание / confirm) — отдельные виджеты, НЕ трогаются.

## Адаптивный путь (новое)
cwd в хедер-справа усекается по доступной ширине:
- влезает целиком → весь путь;
- не влезает → сохраняем корень и последний сегмент, середину схлопываем в `…`
  (`D:\dev\PycharmProjects\ai\ReAct-Agent` → `D:\dev\…\ReAct-Agent`);
- совсем узко → только хвост `…\<последняя папка>`.
Пересчёт на ресайз терминала (`on_resize`). Хелпер — чистая функция
`truncate_path(path, max_cols) -> str` в презентационном слое (`tui/services/…`), с юнит-
тестами на граничные ширины.

## Цвета (сводка; всё из текущей палитры)

| Команды, подсказки | dim | #8b949e |
| Имя модели | ink (контент) | #ebe9e6 |

| Спиннер running/compressing | RUN (amber) | #D4A574 |

сейчас. Палитра-константы зеркалятся в `palette.py` ↔ `styles.tcss` (правим оба).

## Затрагиваемые модули (ориентир, детализирует план)
- `src/tui/screens/main.py` — `compose()` (новая мета-полоса, футер h2, разделители),
  `_compose_header_segments` (хедер-слева/право, welcome, путь), перенос модель/контекст/
  статус в мету, спиннер как персистентный низ трейса.
- `src/tui/widgets/thinking_indicator.py` — состояние `done` (`✓ Выполнил за N`, deep-dim) +
  персистентность (не уничтожать по завершении хода).
- `src/tui/styles.tcss` (+ `palette.py` при необходимости) — `#header`/`#footer` высоты и
  границы, новый `#meta`-блок, разделители между полосами, футер h2.
- `src/tui/services/` — новый чистый хелпер `truncate_path` (+ тесты); возможно вынести
  сборку мета-строки в чистую функцию (презентация, тестируемо).
- `src/tui/branding.py` — строка welcome («Добро пожаловать в GigaCode»); ревизия
  `HEADER_RIGHT` (больше не «F1 help · gc-ua» для главного экрана).

## Вне scope
- Прочие экраны (sessions/help/mcp/config) — их хедеры/футеры не трогаем в этой итерации
  (если только не ломается общий `HEADER_RIGHT`-контракт — тогда точечно).
- Поведение суммаризации/прогона/ask_human/confirm — без изменений.
- Анимация/глифы спиннера — как есть (меняется только текст done-состояния и персистентность).

## Тестирование
- `truncate_path` — юнит-тесты на граничные ширины (целиком / середина-схлоп / только хвост).
- ThinkingIndicator `done` — рендер `✓ Выполнил за N` deep-dim; персистентность (не
  уничтожается по завершении хода — переключается в done).
- Мета-строка — сборка текста (модель ink, контекст-сегмент из meter, бейдж справа) на
  реальном конфиге; свежий экран → `[—]`/`0%`.
- Снапшот-тесты ключевых состояний (покой/прогон/сжатие/ask_human/свежий) — регенерация.
- Регрессия footer-hint (clear/stop/paste) — слот footer-left по-прежнему работает.
