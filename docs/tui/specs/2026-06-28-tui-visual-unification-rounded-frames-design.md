# TUI: визуальная унификация — стартовый экран, баннеры, рамки

Дата: 2026-06-28
Статус: design (согласован визуально через brainstorming visual companion)
Область: `src/tui/` (презентационный слой), снапшот- и юнит-тесты

---

## 1. Цель и мотивация

Привести визуальный слой TUI к единому языку: «симпатичный блок-карточка сверху»
(как ориентир — стартовый экран Claude Code), аккуратные скруглённые рамки вместо
текущих топорных (толстый боковой край + острые углы), и единый стиль box-рамок по
всему интерфейсу.

Задача собрана из обсуждённых требований пользователя:
- Стартовый экран: бренд + MCP в рамке, тэглайн на линии рамки, хедер сохранить.
- Баннеры `ask_human` / `confirm` (read/write/command guard): ровные скруглённые рамки.
- Гуарды: отделить «защитный шлюз» от «вопроса агента» сменой глифа.
- Отвеченные вопросы в трейсе: аккуратная рамка вместо тусклого `? ask_human:`.
- Меню (палитра команд/скиллов/опций) и панели конфига: тоже скруглить.
- Полный аудит рамок: всё, что является box-рамкой, привести к `round`.

## 2. Язык дизайна (принцип, связывающий все изменения)

- **Скруглённая рамка (`border: round`) = «живой/активный» блок:** стартовая карточка,
  баннеры `ask_human`/`confirm`, меню-оверлеи, панели конфига, модальные диалоги.
- **Серая скруглённая рамка = «архив/история»:** отвеченный вопрос в трейсе.
- **Боковая кромка (`border-left`) = реплики/превью:** user-band (teal), tool-preview,
  выбранные карточки — остаются как есть (это намеренные рельсы, не боксы).
- **Одиночные горизонтальные линии = хром-разделители:** низ хедера, верх/низ инпута и
  строк-фильтров, футеры — остаются прямыми (скругление к одной грани неприменимо).
- **Цвет — редкий сигнал:** teal (`$accent`) = сервис/бренд/подтверждение;
  янтарь (`$run-color`) = «агент ждёт тебя» (`ask_human` + маркер вопроса + caution-глиф
  гуарда); серое = хром/история. Тело монохромно.

Скругление в проекте **уже принято де-факто**: диалоги `rename`, `confirm`,
`mass_delete` используют `border: round $accent`. Эта задача доводит до того же
стандарта остальные box-рамки.

## 3. Объём изменений (6 блоков)

### 3.1. Стартовый экран — вариант «A2» (рамка-карточка)

**Файлы:** `src/tui/screens/main.py` (`_show_brand`, `_update_mcp_indicator`,
`_settle_mcp_row`, `_clear_trace`/`_TRACE_HEADER_IDS`), `src/tui/branding.py`,
`src/tui/services/mcp_progress.py` (возможно), `src/tui/styles.tcss`, `src/tui/palette.py`.

**Что:**
- Хедер-полоса (`#header`: путь+сессия) **остаётся без изменений** — вне скролла, виден
  всегда. Геометрию не трогаем (важно: его переиспользуют preview/sessions).
- Бренд-блок (`#brand-block`) оборачивается в **скруглённую teal-рамку-карточку** внутри
  `#trace`:
  - **Слева** — логотип-градиент (`branding.logo_text()`, как сейчас).
  - **Справа** — MCP-блок: живой список серверов с глифами (`⏳/✓/✗`), по готовности
    схлопывается в итог «✓ MCP: все подключены / готов к работе» (текущая логика
    `_update_mcp_indicator` → `_settle_mcp_row`, перенесённая в правую колонку карточки).
  - Раскладка: `Horizontal(logo, mcp)` внутри карточки.
- **Тэглайн «U N I V E R S A L  A G E N T»** — на **нижней линии** рамки через
  `border_subtitle` карточки, цвет dim (`$dim`/`$deep-dim`). Отдельной строки-тэглайна
  (`brand-tagline-row` с двумя `─` и текстом) больше нет — `_show_brand` упрощается.
- **Зазор** между линией хедера и верхом карточки: `margin-top: 1` у карточки (чтобы линия
  хедера и верх рамки не читались сдвоенной линией).

**Цвет/CSS:** новый стиль `#brand-block { border: round $accent; border-subtitle-color:
$dim; margin: 1 1 0 1; padding: 0 1; }`. (`brand-logo` остаётся; `brand-tagline-row`,
`brand-rule`, `brand-tagline` удаляются как осиротевшие.)

**Адаптив (важно):** логотип ~60 колонок + MCP + рамка требуют ширины ≳ 80. На узких
терминалах правая колонка не влезает → fallback: MCP падает **под** логотип внутри
карточки (вертикально, как сейчас). Порог: `logo_width + mcp_width + рамка/паддинги`.
Решение по ширине принимается в `_show_brand`/`on_resize` (ширина доступна через
`self.app.size.width`). Карточка не должна ломаться/переполняться ни на какой ширине.

**Инвариант шапки трейса:** `_TRACE_HEADER_IDS` (бренд + mcp-status переживают
`_clear_trace`). MCP теперь живёт **внутри** карточки → пересмотреть инвариант: карточка
целиком (`#brand-block`) — единственный header-виджет; `#mcp-status-row` больше не
отдельный ребёнок `#trace`, а часть карточки. Обновить `_clear_trace` и ссылки
`_mcp_status_row` соответственно.

**Вариант B (fallback) — НЕ реализуется сейчас, но закладывается:** «только линии»
(хедер + линия под брендом, без боков, тэглайн на нижней линии). Композицию бренда
факторизовать так, чтобы B собирался малой правкой (отдельный CSS-режим/флаг) — после
выката A2 пользователь сравнит вживую в терминале, и B соберём за пару минут при желании.
Это требование к структуре кода, не к поставке.

### 3.2. Баннеры `ask_human` / `confirm` → `round`

**Файлы:** `src/tui/styles.tcss` (`.ask-human-banner`, `.confirm-banner`).

**Что:** убрать `border-left: thick` и острые углы. Поставить ровную `border: round` одного
цвета по периметру:
- `.ask-human-banner { border: round $run-color; }` (янтарь), убрать `border-left: thick`.
- `.confirm-banner { border: round $accent; }` (teal), убрать `border-left: thick`.
Фон-панель `#161A23`, паддинги, `margin: 0 1` — без изменений.

### 3.3. Гуарды (read/write/command) → глиф `⚠`

**Файлы:** `src/tui/widgets/confirm_banner.py` (`compose`, строка `f"? {banner_title}"`).

**Что:** заголовок шлюза рендерить с янтарным caution-глифом вместо `?`:
- Метка: `⚠` (янтарный `$run-color`) + пробел + bright-bold титул. Сейчас один
  `Static(f"? {title}")` — заменить на rich `Text`: amber `⚠` + ` ` + bright title (либо
  два спана). `?` остаётся **только** в самой строке вопроса («Разрешить …?»).
- Заголовки уже приходят от вызывающих (`request_confirm(title=…)`): «Защита чтения»,
  «Защита записи», команда — менять их не нужно. Одна правка в `ConfirmBanner` покрывает
  все шлюзы (read_guard, path_policy, command_guard, url_policy, command_moderation,
  download_file).

**РИСК — ширина глифа:** `⚠` (U+26A0) в части терминалов имеет emoji-presentation
(ширина 1.5–2 ячейки) → ломает выравнивание. Митигация на этапе реализации: проверить
рендер в целевом терминале (Windows Terminal); при проблеме — width-safe замена (`▲` U+25B2
или `!`) или вариационный селектор text-presentation. Финальный глиф фиксируется по факту
проверки, семантика (caution) сохраняется. Зафиксировать выбранный глиф в коде с комментом.

### 3.4. Отвеченный вопрос в трейсе → серая `round`-рамка + янтарный `?`

**Файлы:** `src/tui/services/trace_render.py` (readonly/preview-путь, ~стр. 206),
`src/tui/screens/main.py` (`_on_ask_human_event`, `_unmount_ask_human_banner` — live-путь),
`src/tui/styles.tcss`, `src/tui/palette.py`.

**Что:**
- Серая скруглённая рамка вокруг текста вопроса + **янтарный маркер `?`**; тех-префикс
  `ask_human:` убрать (content = только текст вопроса).
- **Общий хелпер:** вынести построение виджета отвеченного вопроса в `trace_render.py`
  (напр. `build_answered_question_widget(question, *, event_no)`), используемый обоими
  путями — live (`main.py`) и readonly (`render_segments_readonly` / `_render`) — чтобы
  preview-экран и главный экран были идентичны (сейчас оба независимо печатают
  `  ? ask_human: …`).
- Live-механика hidden→reveal сохраняется: виджет монтируется скрытым
  (`hidden`-класс) и раскрывается при схлопывании баннера — новый бордерный виджет должен
  поддерживать `hidden` (через CSS `display:none`, как сейчас у `.ask-human-question`).

**Цвет/CSS:** новый класс, напр. `.answered-question { border: round <frame-archive>;
color: $dim; padding: 0 1; margin: 1 0; }`, маркер `?` — янтарный (`$run-color`) внутри
виджета (rich `Text`). Класс `.ask-human-question.hidden { display: none }` сохраняем
(или переносим на новый класс).

**Альтернативный вариант (fallback) — НЕ реализуется сейчас, но закладывается:**
**янтарная** рамка вместо серой (`border: round $run-color`, «эхо» live-баннера). Основной
выбор — серая (архив-стиль), но цвет рамки факторизовать так, чтобы переключение
серая↔янтарная было правкой одного токена/класса. После выката пользователь сравнит оба
вживую в терминале, и при желании янтарный вариант соберём за минуту. Это требование к
структуре кода, не к поставке (симметрично варианту B стартового экрана в §3.1).

### 3.5. Меню-оверлеи (`.palette`) → `round`

**Файлы:** `src/tui/styles.tcss` (`.palette`).

**Что:** `.palette { border: round $run-color; }` (было `solid`). Одна правка чинит **сразу
4 оверлея** — они шарят класс `.palette`: `CommandPalette` (палитра команд), `SkillPicker`,
`ArgPicker` (опции команд, напр. `/export`), `FilePicker`. Цвет рамки (`$run-color`)
оставляем как есть — меняется только форма.

### 3.6. Панели конфига (`.config-panel`) → `round`

**Файлы:** `src/tui/styles.tcss` (`.config-panel`).

**Что:** `.config-panel { border: round $deep-dim; }` (было `solid`). `border-title-color` /
`border-subtitle-color` уже заданы и работают (панели «пути», «config.yml»). Меняется
только форма углов.

## 4. Цветовые токены

- Дублирование токенов: значения живут в `src/tui/styles.tcss` (`$vars`) и
  `src/tui/palette.py` (константы). **Любая правка/добавление токена — синхронно в оба
  файла** (требование проекта; имена констант зеркалят `$vars`).
- Новый токен: «серый для рамки-архива» (отвеченный вопрос). Кандидат — отдельный
  `$frame-archive` (≈ `#4b525d`, чуть глуше `$deep-dim`) ИЛИ переиспользовать `$deep-dim`.
  Решение принять при реализации, ориентируясь на живой контраст (мок использовал `#4b525d`).
  При добавлении — занести в оба файла.
- Прочие цвета уже существуют: `$accent` (teal), `$run-color` (янтарь), `$dim`, `$deep-dim`.

## 5. Совместимость Textual

- `border: round` — поддерживается, уже используется (`rename`/`confirm`/`mass_delete`).
- `border_subtitle` / `border-subtitle-color` — поддерживается (`config.py` использует
  `border_title`/`border_subtitle` у панелей). Тэглайн на нижней линии карточки реализуем им.

## 8. Риски и митигации

| Риск | Митигация |
|---|---|
| `⚠` шире 1 ячейки → ломает выравнивание | Проверить в целевом терминале; fallback `▲`/`!`; зафиксировать глиф в коде. |
| A2 не влезает по ширине (логотип+MCP+рамка) | Адаптивный fallback: MCP под логотип; карточка не переполняется. |
| MCP перенесён внутрь карточки → ломается инвариант `_TRACE_HEADER_IDS`/settle | Аккуратно обновить инвариант шапки и ссылки `_mcp_status_row`; покрыть `test_mcp_boot_snapshot`/`test_mcp_snapshot`. |
| Рассинхрон токенов styles.tcss ↔ palette.py | Любой токен — в оба файла; код-ревью в радиусе правки. |
| Снапшоты «позеленели» вслепую | Перегенерировать осознанно, глядя на SVG. |
| Два пути рендера отвеченного вопроса разойдутся | Общий хелпер в `trace_render.py` для live и readonly. |

## 9. Вне объёма (явно НЕ делаем)

- **Поле ввода (`#cmdinput` / `TextArea.ask-human-mode`) не трогаем** — ни в обычном
  режиме, ни в `ask_human`. Текущее обычное поле пользователя устраивает.
- **Хедер-полоса** геометрически не меняется.
- **Таблицы в ответах агента** (`markdown_render.py`, `_box.SQUARE`) → `ROUNDED` — НЕ в этом
  заходе (трогает рендер контента и много снапшотов; при желании — отдельной задачей).
- Одиночные горизонтальные линии-разделители и `border-left`-рельсы — остаются прямыми.
- Реализация варианта B стартового экрана — отдельный быстрый follow-up после живого
  сравнения (но структура кода должна делать его дешёвым).

## 10. Критерий готовности

- Все 6 блоков реализованы; стартовый экран = A2 (teal-карточка, MCP справа/адаптивно,
  тэглайн на нижней линии, хедер на месте).
- Все box-рамки в TUI скруглены и единообразны; одиночные линии и рельсы не тронуты.
- Гуарды помечены `⚠` (width-safe), `ask_human` — `?`; отвеченный вопрос — серая
  round-рамка + янтарный `?`, без `ask_human:`, идентично на главном и preview.
- Юнит-тесты зелёные; снапшоты перегенерированы и проверены глазами.
- Поле ввода и геометрия хедера не изменены.
