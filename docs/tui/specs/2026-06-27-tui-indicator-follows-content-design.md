# Дизайн: индикатор «идёт за контентом» трейса (а не всегда внизу)

Дата: 2026-06-27
Статус: дизайн (ожидает ревью)

## Проблема

После выноса индикатора в фиксированную `#indicator-bar` (между `#trace` и `#input-row`)
он всегда прижат к низу (над вводом), потому что `#trace` имеет `height: 1fr` — всегда во
весь доступный рост. Желаемое: когда трейс короткий (начало сессии, контент не доходит до
низа) — индикатор идёт **сразу за контентом**; к низу над вводом он опускается только когда
контент заполнил экран. При этом нельзя вернуть мерцание-наложение стрима (ради чего индикатор
и вынесли из скролла).

## Решение (B): `#trace` сжимается до контента + динамический потолок

`#trace`: `height: 1fr` → **`height: auto`** с **динамическим `max-height`** (= доступное
место). Растёт с контентом до потолка, дальше — скролл (паттерн уже есть в проекте:
`#cmdinput` — `height: auto; max-height: 10`). Новый **`#spacer (height: 1fr)`** между
`#indicator-bar` и `#input-row` забирает остаток, удерживая ввод/футер внизу, когда `#trace`
короткий. Индикатор **остаётся в `#indicator-bar`** (отдельный регион) → наложения нет.

Поведение:
- контент короткий → `#trace` = высоте контента, `#indicator-bar` сразу за ним, `#spacer`
  заполняет низ, ввод/футер внизу;
- контент дорос до потолка → `#trace` упёрся (= `available`) и скроллится, `#spacer` = 0,
  индикатор внизу над вводом (как сейчас).

**Ключ:** рост контента по мере стрима держит сам Textual (`auto` до `max-height`) — нашего
кода на каждый токен/тик НЕТ. Динамичен только сам потолок (меняется редко).

## Компоненты

### 1. Верстка (`compose()` + CSS)
- `compose()` ([main.py:174-186](../../src/tui/screens/main.py#L174)): добавить `#spacer`
  между `#indicator-bar` и `#input-row` (пустой контейнер-распорка).
- CSS (`styles.tcss`): `#trace { height: auto; ... }` (было `1fr`); `#spacer { height: 1fr; }`.
  `max-height` для `#trace` НЕ задаём в CSS — ставится из кода (§2).

### 2. Динамический потолок `#trace` (минимальный, на гарде)
Новый метод `MainScreen._sync_trace_max_height()`:
```
available = screen_h − header_h − input_row_h − footer_h − indicator_bar_h
```
(высоты читаются из `.size.height` соответствующих виджетов; `#indicator-bar` = 0 в простое).
Если значение валидно (>0) и **отличается** от ранее выставленного — `#trace.styles.max_height
= available` (гард против лишних relayout). Вызывается из `_poll_active` безусловно (рано, до
веток run-состояния) — покрывает простой, прогон, ресайз, появление/скрытие индикатора,
многострочный ввод. Рост контента — НЕ здесь (его держит Textual).

### 3. Автоскролл / мерцание — без изменений
- Автоскролл (`_trace_is_at_bottom`/`scroll_end`) не трогаем: короткий `#trace` → скролла нет
  (no-op); упёршийся → как сейчас.
- Мерцания нет: индикатор в `#indicator-bar`; при коротком стриме он плавно съезжает за
  контентом в своём регионе, без перекрытия с `#trace`.

## Тесты (TUI → `uv run pytest`)

- Короткий контент (несколько строк, экран не заполнен): после рендера высота `#trace`
  ≈ высоте контента (`#trace.size.height` заметно меньше доступного), `#indicator-bar` идёт
  сразу за `#trace`, не у низа.
- Высокий контент (строк больше доступного): `#trace.size.height` == `available` (упёрся),
  `#trace.max_scroll_y > 0` (скроллится), индикатор у низа над вводом.
- Гард: повторный `_sync_trace_max_height` без изменения размеров не меняет `max_height`
  (значение стабильно).
- Регресс: `test_trace_autoscroll`, `test_indicator_dock`, `test_thinking_*`, стрим-тесты —
  зелёные.

## Риск / верификация

Первый шаг реализации — **прототип-проверка** Textual-механики: `#trace` `height: auto` +
динамический `max-height` + `#spacer (1fr)` дают (а) сжатие до контента при коротком, (б)
упор+скролл при высоком, (в) индикатор/ввод на местах. Точную формулу `available` (учёт
border'ов `#input-row`, off-by-one) при необходимости подкрутить по факту прогона. Mode-
флапанья нет — `auto+max` непрерывен (нет переключения режимов).

## Вне scope
- Анимация/состояния индикатора, частота стрима, поведение агента — не трогаем.
- `margin-top` индикатора (зазор сверху) — оставляем как есть (недавняя правка).
- Прочая верстка хрома (header/footer) — не трогаем.
