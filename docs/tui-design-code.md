# Дизайн-код TUI

Нормативные правила вида `gc-ua`. Новые правки TUI им следуют; существующие
отступления не мигрируем вне задачи. Пункты помечены: **действует** (код
уже так устроен, есть страж) или **правило для новых правок** (в ленте ещё
не реализовано, пишется так сразу).

## 1. Цвет только из палитры

**Действует.** Все цвета определены в `gc_tui/palette.py`. В `styles.tcss`
и в Python (`rich.Text(..., style=...)`) hex-литералов нет: CSS берёт
`$токен` (переменные инжектятся через `css_variables()`), Python
импортирует константу. Нужного оттенка нет — заводится токен в палитре,
а не литерал по месту.

Страж: `test_palette_sync.py` (`test_no_hex_in_tcss`,
`test_no_hex_in_py_outside_palette`) обходит `*.tcss` и `*.py` пакета, hex
вне комментариев и докстрингов — ошибка. Там же: каждый `$токен` из
tcss есть в `css_variables()`, и словарь совпадает с константами.

Имя токена: константа `DEEP_DIM` — переменная `$deep-dim`.

Граница: цвета встроенной темы Textual (всплывающие уведомления,
тултипы) и кодовые темы Pygments / TextArea от фона терминала не
пересчитываются — палитра управляет только своими токенами.

## 2. Токены и что чем красится

| Токен | Назначение |
|---|---|
| `BG` | фон экрана |
| `INK` | основной текст; только текущее (см. ступени в п. 5) |
| `BRIGHT` | заголовки и акценты текста ярче основного |
| `SUB_INK` | светло-серый: закончившееся; второстепенные ключи |
| `DIM` | глагол и подписи, подсказки |
| `NOTE_INK` | ремарки и сводки (`.line-note`, `.line-summary`) |
| `MUTED`, `DEEP_DIM` | объекты в деталях, номера строк, приглушённые рамки |
| `ACCENT` | фокус, ховер кликабельного, фирменный teal |
| `CODE`, `CODE_BLOCK`, `TOOL_NAME` | инлайн-код и имена; блоки кода; имена тулов |
| `SKILL` | имя скилла в поле ввода и в строке вызова (светло-голубой; отличать от сиреневого `CODE`); в реплике имя скилла цветом текста |
| `OK`, `ERR`, `WARN`, `INFO`, `RUN_COLOR`, `OLIVE`, `BRAND` | семантика: успех, ошибка, предупреждение, инфо, выполняется, градиент логотипа, бренд |
| `BAND_BG`, `BLOCK_BG` | полоса баннеров; карточка блочного контента (код, таблицы, диффы) |
| `USER_BAND_BG`, `QUEUE_BG` | подложка реплики пользователя; тихая реплика (тише, между `BG` и `USER_BAND_BG`) |
| `LIST_SELECT_BG` | выбранная строка списков и пикеров (палитра, `/diff`, настройки, онбординг, `/mcp`); не связана ни с подложкой реплики, ни с подсветкой ленты |
| `HIGHLIGHT_BG`, `CARD_SELECT_BG` | подсветка: фокус и выделение строки ленты, ховер накладок ленты (светлее `USER_BAND_BG`); выбранная карточка |

Ступени фона ленты по светлоте: `BG` < `QUEUE_BG` < `USER_BAND_BG` <
`HIGHLIGHT_BG`. Тихая реплика тише обычной, подсветка ярче подложки
реплики — фокус на реплике различим (страж
`test_quiet_band_below_band_below_highlight`).
| `OVERLAY_BG`, `ZEBRA_BG` | фон оверлеев и модалок; чётная строка зебры |
| `FRAME_ARCHIVE`, `TRACK`, `TEXT_ON_FILL` | рамка «архив»; трек метра; текст на цветной заливке |
| `DIFF_*` | диффы: фоны строк и акценты — примесь `OK`/`ERR` к `BG`; номер строки и маркер — `OK`/`ERR` |
| `*_SHADES` | рампы анимаций (`GLOW`, `PROCESSING`, `VALIDATING`) |

Цвет несёт смысл: статус, счётчик правок, дифф, ошибка. Декоративного
цвета нет.

Выделение — `INK` жирным: жирный `**…**` и заголовки ответа (`.line-bold`,
`.line-heading-1`, `.line-heading-2`, `markdown_render._bold_style`), как и
слово заголовка блока вызовов. `ACCENT` для выделения в прозе не
используется (решение владельца 2026-10-23).

Плашки результата в `/settings`: зелёная ✓ (`OK`) — успех, в том числе
когда сохранённое применится только со следующего запуска; янтарная ⚠
(`WARN`) — только настоящая проблема: не сохранено, не удалось, записано,
но перекрыто другим слоем. Путь файла в плашке — с домашним каталогом
через `~`.

## 3. Поля формы по классу

**Действует.** Вид поля ввода задаёт класс `form-field`, а не id поля.
`PasteInput` вешает его сам в `__init__` (Textual применяет
`DEFAULT_CLASSES` только при `classes=None`, поэтому класс добавляется
явно). Правила: `.form-field`, `.form-field:focus`, `.form-field.set-framed`
(скруглённая рамка `RUN_COLOR` в `/settings`), `.form-field.set-readonly`.
Приглушённая рамка полей-токенов — `.form-field.set-framed.set-muted:disabled`:
класс `set-muted` нужен, потому что поля-факты голоса тоже `disabled`, но
рамку держат прежней.

Правило для новых полей: класс, не селектор по id. Поле без класса получает
дефолтную рамку Textual из глифов, которых нет в консольных шрифтах.

Страж: `test_styles_field_ids.py` (правила стоят на классе; в tcss нет
селекторов id полей ввода; рамка токена приглушена, рамка поля-факта нет).

## 4. Колонки ленты

**Действует.** Отступ уровня — один источник: `trace_render.LEVEL_INDENT`
и `level_prefix(level)`; живая лента и превью строят строки одними
билдерами `trace_render`.

- Глиф любого события (`●` ответа, `●`/`○`/`•` вызова, `›` реплики,
  `!` строки без владельца) стоит в колонке `●` реплики агента. Каждый
  уровень вложенности сдвигает на +2: событие уровня `n` — в колонке
  `1 + 2n`.
- Тулы отличаются глифом и приглушённым цветом, не отступом.
- Глифы статуса вызова — круги, исход несёт цвет (статус строки и цвет её
  строки `└`). Знаки — константы `gc_tui.services.trace_glyphs`, таблица
  исход → глиф и цвет — `ToolCallRow`. Итог хода «✕ Ошибка» и «└ ✕ скилл
  … не найден» — не вызов: у них свой `ERROR_GLYPH` (`✕`). Под «✕ Ошибка»
  — причина `└ <класс>: <текст>` (`DIM`, переносится до трёх строк с
  отступом под текстом, дальше `…`); берётся из записи итога хода в
  файле треда (поле `error`), только у свежей строки итога в ленте. Прочие экраны
  (настройки, онбординг, MCP, формы) держат свой `✗`. Чек-лист держит свои
  `○ → ✓`.

  | Глиф | Исход | Цвет |
  |---|---|---|
  | `●` | успех, хвост ` · сводка` | `OK` |
  | `●` | ошибка тула; строка `└` — `ERR` | `ERR` |
  | `○` | отказ: режим, защита, судья, человек; строка `└` — `REFUSED` | `REFUSED` |
  | `○` | стоп пользователя, лимит, несостоявшаяся проверка судьи, прервано | `DIM` |
  | `●` | идёт — мигает янтарным, исчезая | `RUN` 0,5 с ↔ пустая клетка 0,7 с |
  | `●` | ждёт человека (подтверждение, `ask_human`) — не мигает | `RUN` |
  | `•` | ещё не начат | `DIM` |

  Ожидание человека: `●` идущих строк и заголовка блока с ждущим членом
  не мигает, таймер стоит. Строка спросившего разрешения вызова (у члена
  блока — без глифа, как всегда) вместо таймера несёт ` · ждёт
  разрешения` цветом живого таймера `RUN`; слово строки прежнее. Таймер
  ленты и индикатора хода — живой и застывший — с целой секунды, одно
  правило `duration_format.format_timer`: `· 0с` не бывает. Глифа `‖` в
  ленте нет.

  `REFUSED` — приглушённый оранжевый `_mix(BG, WARN, 0.55)`; в теме auto
  пересчитывается от фона. В ленте `REFUSED` — кружок отказа, его строка
  `└` причины (у одиночной строки и у члена блока) и счётчик ` · N
  отказов` заголовка блока. Отказы в слоте футера — `WARN` (все отказы
  слота; подсказки и советы — цветом подсказки).

  Исход определяет один классификатор маппера (`trace_mapper.result_stop`,
  тексты отказа — `services/tool_refusal.py`) для живой ленты, превью и
  вложенных вызовов из записи субагента.
- Буллеты прозы и вызовов — в одной колонке; сводка — на колонке текста
  без буллета.
- Следствие события (дифф, строки `└`: ошибка, отказ, пометка, «скилл не
  найден») — на +2 от его глифа, внутри виджета события.
- Перенос следствия — под текстом после `└ `: строку собирает
  `trace_render.build_consequence_line` (отступ и `└ ` отдельной колонкой,
  тело — в колонке 1fr, как подпись строки вызова).
- Между событиями пустая строка; дифф и строки `└` прижаты к своей
  строке без зазора. Внутри блока субагента пустых строк нет совсем
  (класс `-in-agent`), между членами блока — тоже; в блоке правок и под
  `Ran` пустая строка — только после видимого файла с телом (превью
  диффа); файлы без тела (`Deleted`, бинарь с размером, правка без
  записи) идут подряд.
- Блоки вызовов (спека P4 §3.1, `docs/tui.md`, «Трейс») — сетка колонок
  от колонки `●` своего уровня: 0 — глиф события и заголовка блока; 2 —
  текст заголовка, `└ ` перед первым членом или маркером `… ещё N`,
  следствие `└` одиночной строки, дифф одиночной правки; 4 — члены
  группы, управление (`… ещё N` над членами, `+ ещё N строк` или
  `− свернуть` прямо под тем, что раскрывает: под диффом своего файла,
  под выводом `Ran`; `− свернуть группу` окна — в самом низу блока), диффы
  членов, продолжение превью
  вывода и многострочной команды; 6 — `└` следствия члена. У членов
  группы глифа нет никогда. Под `Agent` — строка задачи: `└` в колонке
  2, текст в 4 (перенос — тоже в 4), `DIM`, не длиннее двух строк. Маркер
  окна `Agent` `… ещё N` — без `└`, в колонке 2, то есть в колонке глифов
  вложенных событий, ниже задачи и всех следствий `Agent` (`└` причины
  сбоя или стопа). Вложенное событие субагента — на +2 от глифа `Agent`,
  дальше та же сетка от него; сдача субагента — последнее событие окна:
  `Finishing` с янтарным глифом, `Finished  <solution_type>` у принятой,
  `Finish` с глифом и причиной `ERR` у отвергнутой. `− свернуть группу`
  раскрытого окна `Agent` — последней строкой его блока там же, где
  маркер окна: в колонке 2, без `└`. Счётчики правки `(+a −r)` — обе части всегда, `+a` `OK`,
  `−r` `ERR`, скобки `INK`, как объект слева. Решения
  принимает модель `gc_tui.services.tool_blocks`, виджеты ставит
  исполнитель `gc_tui.widgets.tool_blocks_view`.
- Строка без владельца — `! текст` в колонке `●` (`ERR` для ошибок,
  `WARN` для предупреждений), со своей пустой строкой сверху. Отказ или
  стоп, к которому нет строки вызова, — не `!`, а `○ кто: почему`: глиф
  цветом исхода (`REFUSED` или `DIM`), текст `DIM`
  (`trace_render.build_orphan_result_row`).
- Место строки хода: строка итога хода (`widgets/turn_line.py`,
  `TurnLine`) — событие уровня 0 в ленте: глиф в колонке `●`, пустая
  строка сверху, на месте записи итога — после последнего события хода и
  до следующей реплики. Строка последнего хода свежая (`-latest`): справа
  сводка правок (кликабельна), под `✕ Ошибка` — причина `└`; с началом
  следующего хода оседает — остаётся голова. Цвет — `DEEP_DIM` у обеих:
  при оседании строка не меняет вид, только теряет сводку и причину.
  Пока стоит бар, строка конца хода ждёт за ним (`-held`) и встаёт тем же
  движением, что уходит бар. Голова строки (`глиф Слово за N · время`) —
  одна функция `turn_outcome.turn_head` для ленты и превью; строку
  собирает `trace_render.build_turn_line`. Индикатор хода в
  `#indicator-bar` показывает только работу, его глиф — в той же колонке
  `●`.
- Раскладка одна для живой ленты и превью.
- Реплика в очереди (отправлена во время хода) — подложка `QUEUE_BG`,
  маркер `›` — `MUTED`, текст — `DIM`; подсказка
  `в очереди · ↑ — изменить до отправки` — `MUTED` без подложки, только
  под последней ожидающей. Впущенная реплика — обычная (`USER_BAND_BG`).
- Тихая реплика — один вид у реплики в очереди и у липкой реплики над
  лентой: подложка `QUEUE_BG`, маркер `›` — `QUIET_REPLY_MARK` (= `MUTED`);
  текст у реплики в очереди — `QUIET_REPLY_INK` (= `DIM`), у липкой бледнее —
  `STICKY_REPLY_INK` (= `DEEP_DIM`, решение 32; ink — параметр
  `quiet_line`); имя скилла (полный id с пакетом) цветом текста своей
  реплики, отдельного токена нет; ховер липкой — `HIGHLIGHT_BG`. Маркер и `/имя текст` строят одни построители
  `UserReplyContainer` (`_quiet_lead`, `_quiet_body`): первая строка
  реплики в очереди и строка липкой (`quiet_line`); цвета — из этих
  токенов (в TCSS — `$queue-bg`, `$quiet-reply-*`); вид меняется в одном
  месте. Реплика в обычном состоянии рисует имя скилла цветом текста (`INK`).
- Накладки ленты «не внизу» (`widgets/trace_overlays.py`) — поверх
  экрана, высоты ленты не занимают, фокус не берут; внизу их нет.
  Липкая реплика `StickyReply` — первая строка ленты, подложка
  `QUEUE_BG` («тихая реплика», см. ниже), на ховер светлеет до
  `HIGHLIGHT_BG` на всю строку (общий фон ховера обеих накладок, не
  `USER_BAND_BG`; текст не меняет цвет — то же исключение из `.trace-action:hover`, что и у плашки), `›` — `MUTED`, текст — `DIM` в одну строку с `…`.
  Плашка `ScrollEndPill` — по центру ленты, в ряду прямо над баннером,
  списком из поля ввода или рамкой поля: во время хода — в нижней строке
  бара индикатора, без бара — в нижнем зазоре ленты (баннеры и списки её
  не прячут, индикатор не задевает; бар встаёт и уходит — плашка на
  месте), фон `USER_BAND_BG`,
  текст `INK`; ховер — светлее фон (`HIGHLIGHT_BG`, тот же, что у липкой реплики), текст не меняет цвет:
  явное исключение из общего `.trace-action:hover` (п. 6). Подпись
  считает видимые новые реплики агента с ухода от низа (`↓ N новых
  сообщений · …`; убранная попытка ответа не считается); при потере фокуса окна терминала не меняется.

Страж: `test_trace_columns.py` (колонки по уровням, общий источник
отступа, одна раскладка у живой ленты и превью, глиф индикатора хода в
колонке `●`, пустая строка перед каждым событием верхнего уровня, внутри
субагента — без пустых строк); сетка блоков — `gc_testkit.trace_grid`
(`assert_trace_grid` по отрендеренной ленте в тестах блоков: живая лента,
превью, субагент, новые эталоны `test_snapshot_tool_blocks.py`).

## 4a. Раскладка главного экрана

**Действует.** Поле ввода и подвал всегда прижаты к низу экрана, в том числе в
пустой новой сессии: `#trace` — `1fr` (ширина `100%`), пустота короткой ленты
остаётся между бренд-карточкой и вводом. Всё остальное складывается над вводом,
снизу вверх: список из поля ввода или баннер (подтверждение, план, вопрос
агента), над ними — бар индикатора (только во время хода; под баннером скрыт),
выше — лента. Нижний ряд ленты — всегда пустой зазор (`margin` `#trace`):
у заполненной ленты между её последней строкой и рамкой поля ввода в покое —
ровно одна пустая строка.

Списки из поля ввода (палитра, `/skill`, значения ручек, `@`) монтируются
перед `#input-row` (`TraceScreen._mount_input_overlay`) и раскрываются вверх:
поднимают ленту, а не накрывают её. Ввод не двигается ни при открытии, ни при
фильтре, ни при закрытии. Потолок списка — половина экрана с запасом строк ленте
(`_sync_chrome_caps`); прижатая к низу лента остаётся прижатой при любой смене
высоты хрома (`_keep_trace_bottom`). Порядок строк не переворачивается: лучшее
совпадение вверху.

Новый элемент хрома встаёт над вводом, не под ним. Страж:
`test_input_pinned_bottom.py`.

## 5. Ступени яркости ленты

**Правило для новых правок.**

- `INK` (белым) — только текущее: идущий вызов, `Running`-команда,
  заголовки блоков (слово жирным), имена файлов в правках, имя субагента.
- `SUB_INK` (светло-серым) — закончившееся: команда `Ran …`, объект
  законченной одиночной строки (MCP, `Skill` — имя скилла `SKILL`),
  глагол `Added` / `Edited` / `Deleted` под командой.
- Одиночная строка: слово `INK` жирным, объект идущей — `INK`, после
  конца — `SUB_INK`; путь одиночной правки и имя субагента — `INK`
  всегда.
- Внутри `Explored` и `Fetched` (и в идущей, и в закончившейся группе):
  глагол `DIM`, объект и хвост `MUTED`, текущий член — `INK`.
- При завершении группы меняются глиф и заголовок, цвета строк не
  «прыгают». Синего в ступенях нет.

## 6. Ховер и фокус

**Действует.** Кликабельные фразы на ховер получают
`color: $accent`, и красит их один общий класс, а не правило по месту.
Это класс `.trace-action` (`.trace-action:hover` в `styles.tcss`): им
помечены ❐, «… ещё N строк», `− свернуть` тела метки сжатия; других правил ховера с `$accent` для фраз
ленты нет (страж `test_styles_trace_action.py`). Исключение — плашка
`↓ в конец`: на ховер светлеет её фон (`HIGHLIGHT_BG`, общий с липкой репликой), цвет текста
прежний. Строки событий и заголовки блоков ховера не красят: фокус и
выделение — `$highlight-bg` на `:focus` (реплика тоже), раскрытие кликом или Enter.

## 7. Тема `auto` / `gigacode`

Ключ `tui.theme` (`auto` по умолчанию, `gigacode`); схема, `config.default.yml`
и `demo_config.yml` синхронны.

- **gigacode** — собственная тёмная палитра: литералы `palette.py`, вид не
  зависит от терминала. Эталон снапшотов.
- **auto** — фон TUI равен фону терминала, поверхности и зависящие от фона
  токены пересчитываются от него (`palette.apply_background`).

Выбор темы (`palette.select_palette`): не `auto` — `gigacode` без пробы;
`auto` — проба `services/terminal_caps.query_background` (OSC 11 с DA1 в
качестве сторожа, таймаут 0,1 с, режим терминала и `TCSAFLUSH` в
`finally`, чтобы поздний ответ не попал во ввод). Нет ответа (не TTY,
Windows, `TERM` пустой или `dumb`, tmux без проброса, таймаут) или фон,
на котором текст палитры (`INK` и `DIM`) читается хуже контраста WCAG 3
(`MIN_TEXT_CONTRAST`: светлые и цветные фоны средней яркости) — `gigacode`.

Тема выбирается один раз при старте; горячего переключения нет. Переключатель
— `/settings` → «Внешний вид»: пишет `tui.theme`, действует со следующего
запуска. Имя каждого значения схемы — в `THEME_NAMES` секции (страж
`test_settings_appearance.py`).

Порядок старта: тема применяется до импорта `gc_tui.app`. Модули берут
токены через `from gc_tui.palette import X`, значение фиксируется при
импорте, поэтому `main()` проверяет Textual через `find_spec`, выбирает
палитру и только потом импортирует приложение. Страж порядка:
`test_theme_startup.py`.

Что как считается в `auto`:

- `BAND_BG`, `BLOCK_BG` — смешивание `BG` с `INK`; при фоне `gigacode`
  совпадают с литералами.
- Синеватые поверхности (`CARD_SELECT_BG`, `USER_BAND_BG`, `LIST_SELECT_BG`,
  `OVERLAY_BG`, `ZEBRA_BG`, `TRACK`) — смешивание `BG` с одним тоном
  `SURFACE_TINT`; веса выведены из литералов. Смена тона (например, на
  белый) — одна строка.
- `QUEUE_BG` — смешивание `BG` с пересчитанным `USER_BAND_BG` (доля 0.5).
- `HIGHLIGHT_BG` — смешивание пересчитанного `USER_BAND_BG` с `INK`
  (доля 0.12).
- `DIFF_*` сдвигаются вместе с фоном (литерал + (фон − фон `gigacode`)), чтобы
  различимость строк диффа не зависела от фона.
- Рампы анимаций в `gigacode` — литералы; в `auto` пересчитываются от фона
  (пик рампы остаётся).
- Акценты, текст и `SCREEN_SELECTION_BACKGROUND` от фона не зависят.

Стражи: `test_palette_background.py` (в `gigacode` литералы точны, в `auto`
поверхности сходятся с литералами, стражи различимости держатся на
типичных тёмных фонах), `test_palette_sync.py`.

## 8. Как добавить цвет

1. Назвать слой и смысл: чем красим и в чём отличие от существующего токена.
2. Есть подходящий токен — взять его. Нет — завести константу в
   `palette.py` и ключ в `css_variables()`.
3. Токен зависит от фона — добавить в пересчёт темы `auto`
   (`_derived`) и проверить стражи различимости.
4. Эталоны снапшотов в `gigacode` не меняются; `--snapshot-update` вслепую
   запрещён.
