# Дизайн-код TUI

Нормативные правила вида `gc-ua`. Новые правки TUI им следуют; существующие
отступления не мигрируем вне задачи. Пункты помечены: **действует** (код
уже так устроен, есть страж) или **правило для новых правок** (в ленте ещё
не реализовано, пишется так сразу).

## 1. Цвет только из палитры

**Действует.** Все цвета определены в `gc_tui/palette.py`. В `styles.tcss`
и в Python (`rich.Text(..., style=...)`) hex-литералов нет: CSS берёт
`$токен` (переменные инжектятся через `css_variables()`), Python
импортирует константу. Нужного оттенка нет — заводится токен в палитре,
а не литерал по месту.

Страж: `test_palette_sync.py` (`test_no_hex_in_tcss`,
`test_no_hex_in_py_outside_palette`) обходит `*.tcss` и `*.py` пакета, hex
вне комментариев и докстрингов — ошибка. Там же: каждый `$токен` из
tcss есть в `css_variables()`, и словарь совпадает с константами.

Имя токена: константа `DEEP_DIM` — переменная `$deep-dim`.

Граница: цвета встроенной темы Textual (всплывающие уведомления,
тултипы) и кодовые темы Pygments / TextArea от фона терминала не
пересчитываются — палитра управляет только своими токенами.

## 2. Токены и что чем красится

| Токен | Назначение |
|---|---|
| `BG` | фон экрана |
| `INK` | основной текст; только текущее (см. ступени в п. 5) |
| `BRIGHT` | заголовки и акценты текста ярче основного |
| `SUB_INK` | светло-серый: закончившееся; второстепенные ключи |
| `DIM` | глагол и подписи, подсказки |
| `NOTE_INK` | ремарки и сводки (`.line-note`, `.line-summary`) |
| `MUTED`, `DEEP_DIM` | объекты в деталях, номера строк, приглушённые рамки |
| `ACCENT` | фокус, ховер кликабельного, фирменный teal |
| `CODE`, `CODE_BLOCK`, `TOOL_NAME` | инлайн-код и имена; блоки кода; имена тулов |
| `SKILL` | имя скилла (светло-голубой; отличать от сиреневого `CODE`) |
| `OK`, `ERR`, `WARN`, `INFO`, `RUN_COLOR`, `OLIVE`, `BRAND` | семантика: успех, ошибка, предупреждение, инфо, выполняется, градиент логотипа, бренд |
| `BAND_BG`, `BLOCK_BG` | полоса баннеров; карточка блочного контента (код, таблицы, диффы) |
| `USER_BAND_BG`, `USER_PENDING_EDGE` | подложка реплики пользователя; кромка неотправленной реплики |
| `FOCUS_BG`, `CARD_SELECT_BG` | строка в фокусе; выбранная карточка |
| `OVERLAY_BG`, `ZEBRA_BG` | фон оверлеев и модалок; чётная строка зебры |
| `FRAME_ARCHIVE`, `TRACK`, `TEXT_ON_FILL` | рамка «архив»; трек метра; текст на цветной заливке |
| `DIFF_*` | диффы: фоны строк и акценты — примесь `OK`/`ERR` к `BG`; номер строки и маркер — `OK`/`ERR` |
| `*_SHADES` | рампы анимаций (`GLOW`, `PROCESSING`, `VALIDATING`, `PULSE`) |

Цвет несёт смысл: статус, счётчик правок, дифф, ошибка. Декоративного
цвета нет.

Плашки результата в `/settings`: зелёная ✓ (`OK`) — успех, в том числе
когда сохранённое применится только со следующего запуска; янтарная ⚠
(`WARN`) — только настоящая проблема: не сохранено, не удалось, записано,
но перекрыто другим слоем. Путь файла в плашке — с домашним каталогом
через `~`.

## 3. Поля формы по классу

**Действует.** Вид поля ввода задаёт класс `form-field`, а не id поля.
`PasteInput` вешает его сам в `__init__` (Textual применяет
`DEFAULT_CLASSES` только при `classes=None`, поэтому класс добавляется
явно). Правила: `.form-field`, `.form-field:focus`, `.form-field.set-framed`
(скруглённая рамка `RUN_COLOR` в `/settings`), `.form-field.set-readonly`.
Приглушённая рамка полей-токенов — `.form-field.set-framed.set-muted:disabled`:
класс `set-muted` нужен, потому что поля-факты голоса тоже `disabled`, но
рамку держат прежней.

Правило для новых полей: класс, не селектор по id. Поле без класса получает
дефолтную рамку Textual из глифов, которых нет в консольных шрифтах.

Страж: `test_styles_field_ids.py` (правила стоят на классе; в tcss нет
селекторов id полей ввода; рамка токена приглушена, рамка поля-факта нет).

## 4. Колонки ленты

**Правило для новых правок** (раскладка ленты приводится к нему отдельно).

- Глиф любого события (тул, субагент, дифф) стоит в колонке ● реплики
  агента. Каждый уровень вложенности сдвигает на +2.
- Тулы отличаются глифом и приглушённым цветом, не отступом.
- Буллеты прозы и вызовов — в одной колонке; сводка — на колонке текста
  без буллета.
- Между событиями пустая строка; дифф и вывод вызова прижаты к своей
  строке без зазора.
- Раскладка одна для живой ленты и превью.

## 5. Ступени яркости ленты

**Правило для новых правок.**

- `INK` (белым) — только текущее: идущий вызов, `Running`-команда,
  заголовки блоков, имена файлов в `Edited`.
- `SUB_INK` (светло-серым) — закончившееся: `Ran …`, `Fetched …`, MCP.
- Внутри `Explored` (и в идущей, и в закончившейся группе): глагол `DIM`,
  объект `MUTED`.
- При завершении группы меняются глиф и заголовок, цвета строк не
  «прыгают». Синего в ступенях нет.

## 6. Ховер и фокус

**Правило для новых правок.** Кликабельные фразы на ховер получают
`color: $accent`, и красит их один общий класс, а не правило по месту.
Факт сегодня: таких правил два, локальных, в `styles.tcss` —
`.diff-more:hover` и `.block-copy:hover`; общий класс — цель, не
реальность. Строки событий и заголовки блоков ховера не красят: фокус и
выделение — `$focus-bg` на `:focus`, раскрытие кликом или Enter.

## 7. Тема `auto` / `gigacode`

Ключ `tui.theme` (`auto` по умолчанию, `gigacode`); схема, `config.default.yml`
и `demo_config.yml` синхронны.

- **gigacode** — собственная тёмная палитра: литералы `palette.py`, вид не
  зависит от терминала. Эталон снапшотов.
- **auto** — фон TUI равен фону терминала, поверхности и зависящие от фона
  токены пересчитываются от него (`palette.apply_background`).

Выбор темы (`palette.select_palette`): не `auto` — `gigacode` без пробы;
`auto` — проба `services/terminal_caps.query_background` (OSC 11 с DA1 в
качестве сторожа, таймаут 0,1 с, режим терминала и `TCSAFLUSH` в
`finally`, чтобы поздний ответ не попал во ввод). Нет ответа (не TTY,
Windows, `TERM` пустой или `dumb`, tmux без проброса, таймаут) или фон,
на котором текст палитры (`INK` и `DIM`) читается хуже контраста WCAG 3
(`MIN_TEXT_CONTRAST`: светлые и цветные фоны средней яркости) — `gigacode`.

Тема выбирается один раз при старте; горячего переключения нет. Переключатель
— `/settings` → «Внешний вид»: пишет `tui.theme`, действует со следующего
запуска. Имя каждого значения схемы — в `THEME_NAMES` секции (страж
`test_settings_appearance.py`).

Порядок старта: тема применяется до импорта `gc_tui.app`. Модули берут
токены через `from gc_tui.palette import X`, значение фиксируется при
импорте, поэтому `main()` проверяет Textual через `find_spec`, выбирает
палитру и только потом импортирует приложение. Страж порядка:
`test_theme_startup.py`.

Что как считается в `auto`:

- `BAND_BG`, `BLOCK_BG`, `USER_PENDING_EDGE` — смешивание `BG` с `INK` /
  `ACCENT`; при фоне `gigacode` совпадают с литералами.
- Синеватые поверхности (`FOCUS_BG`, `CARD_SELECT_BG`, `USER_BAND_BG`,
  `OVERLAY_BG`, `ZEBRA_BG`, `TRACK`) — смешивание `BG` с одним тоном
  `SURFACE_TINT`; веса выведены из литералов. Смена тона (например, на
  белый) — одна строка.
- `DIFF_*` сдвигаются вместе с фоном (литерал + (фон − фон `gigacode`)), чтобы
  различимость строк диффа не зависела от фона.
- Рампы анимаций в `gigacode` — литералы; в `auto` пересчитываются от фона
  (пик рампы остаётся).
- Акценты, текст и `SCREEN_SELECTION_BACKGROUND` от фона не зависят.

Стражи: `test_palette_background.py` (в `gigacode` литералы точны, в `auto`
поверхности сходятся с литералами, стражи различимости держатся на
типичных тёмных фонах), `test_palette_sync.py`.

## 8. Как добавить цвет

1. Назвать слой и смысл: чем красим и в чём отличие от существующего токена.
2. Есть подходящий токен — взять его. Нет — завести константу в
   `palette.py` и ключ в `css_variables()`.
3. Токен зависит от фона — добавить в пересчёт темы `auto`
   (`_derived`) и проверить стражи различимости.
4. Эталоны снапшотов в `gigacode` не меняются; `--snapshot-update` вслепую
   запрещён.
