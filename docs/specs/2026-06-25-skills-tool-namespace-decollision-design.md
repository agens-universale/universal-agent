# Дизайн: устранение префиксной коллизии в неймспейсе skills-тулов

Дата: 2026-06-25
Статус: дизайн (ожидает ревью)

## Проблема

Слабая модель (`vllm/DeepSeek-V4-Flash-262k`, `tool_choice: auto`, streaming) на
скилле `qa-tc-generation` бесконечно вызывает `skills_load_reference` вместо
`skills_load`, не может переключиться, прогон крутится до `max_steps`.

### Корневая причина (подтверждена логом)

Из реального лога прогона (`agent_main_1782402083613_820091ab.log`):

- Бэкенд отдаёт `tool_choice: "auto"`, **без** guided/grammar-decoding —
  имя функции генерится свободно, токен за токеном.
- За прогон: `skills_load_reference` — 18 реальных вызовов, `skills_load` — **0**,
  `skills_load_asset` — **0**. При этом свободно зовутся `skills_list` (×2) и
  ~30 разных `mcp_sbertrack_*`, `exec_python`, `turn_ask_human`.
- Канал прозы и канал tool-call расходятся: ассистент пишет «сейчас вызову
  `skills_load`» — и тут же эмитит `skills_load_reference` (десятки раз подряд,
  включая два прямых требования пользователя «skills_load, не reference»).

Механизм — связка трёх факторов:

1. **Самоподдерживающийся повтор.** В chat_completions вся история (18 вызовов
   `skills_load_reference(...)`) шлётся назад каждый запрос — сильнейший few-shot
   «делай так же» для слабой модели.
2. **Коучащая ошибка реестра.** `Reference 'task' not found... Available
   references: report_templates, test_case_format` удерживает модель в рамке
   «подбери другой reference», а не «смени инструмент».
3. **Префиксная коллизия имён — делает короткое имя недостижимым.**
   `skills_load` — строгий префикс `skills_load_reference`/`skills_load_asset`.
   В позиции tool-call'а модель в собственной истории генерации после токенов
   `skills_load` видела **только** суффикс `_reference`/`_asset`, ни разу —
   терминатор имени. Автогрессивно она не обрывает имя на префиксе, а дописывает
   виденный суффикс.

**Дифференциальное доказательство:** недостижим ровно один тул — `skills_load`,
единственное отличие которого в том, что он строгий префикс залипшего
`skills_load_reference`. Все имена, не вложенные в аттрактор, зовутся свободно.

Это не баг диспетчера (имя берётся дословно из `tool_calls[].function.name`,
`src/utils/convertations.py:118`, без подстрочного матчинга) и не грамматика —
это ловушка, заложенная самими именами тулов.

## Решение

Переименовать skills-тулы так, чтобы ни одно имя не содержалось в другом, сохранив
семейный префикс `skills_` и глагол:

| было                     | стало                   |
| ------------------------ | ----------------------- |
| `skills_load_reference`  | `skills_read_reference` |
| `skills_load_asset`      | `skills_read_asset`     |
| `skills_load`            | без изменений           |
| `skills_list`            | без изменений           |
| `skills_run_script`      | без изменений           |

Финальный набор `skills_{list, load, run_script, read_reference, read_asset}` — ни
одно имя не является префиксом другого (`skills_load` расходится с
`skills_read_*` на 8-м символе `l`/`r`). Общий префикс `skills_` безопасен:
`skills_list`/`skills_load` так и сосуществовали без проблем; фатально именно полное
вложение, и оно уходит.

Семантическая асимметрия глаголов точна, а не случайна: `load` — активировать скилл
в контекст (первый шаг); `read` — достать вспомогательный файл уже загруженного
скилла.

**Отклонено:** `skills_reference_load`/`skills_asset_load` (глагол-последним —
читается коряво); `skills_reference`/`skills_asset` (теряется глагол).

### Обратная совместимость — без алиасов

Чистое переименование, без alias-механизма. Безопасно:

- Внутри кода никто не зовёт эти тулы по строковому имени программно — старые имена
  встречаются только в определениях тулов, тексте доставки, тестах и `SKILL.md`
  (текст для модели, не вызовы).
- Список тулов отдаётся свежим каждый запрос — корректная модель сразу берёт новое
  имя.
- Краевой случай (резюм треда, уже застрявшего в петле, где модель копирует старое
  имя из истории) self-healing: диспетчер вернёт `"... - there is not such tool on
  client"` как tool-output, новое имя тут же в списке, и — ключевое — после снятия
  коллизии модель **способна** переключиться (до фикса не могла вовсе). Миграция
  истории тредов не требуется.

## Компоненты и слои

### 1. `src/tools/skills/skills_tools.py` — владелец имён

- Переименовать ключи словаря и `spec.name` двух тулов на `skills_read_reference` /
  `skills_read_asset`.
- Обновить кросс-ссылки в описаниях: `skills_load` упоминает siblings
  («before skills_load_reference or skills_load_asset» → новые имена);
  `skills_read_reference`/`skills_read_asset` сохраняют «call skills_load(skill_id)
  FIRST».

### 2. `src/tools/skills/skill_delivery.py` — текст доставки скилла

Перевести императив доставки на новые имена («грузи references через
`skills_read_reference`», «assets через `skills_read_asset`»).

### 3. Репо-скиллы (механически)

`skills/skill-creator/SKILL.md`, `skills/supercoder/writing-skills/SKILL.md`,
`skills/supercoder/{test-driven-development,systematic-debugging}/SKILL.md`,
`skills/skill-creator/assets/completion_report_template.md` — на новые имена, для
консистентности обучающего контента.

## Тесты (TDD: сначала RED)

- **Регресс на контейнмент (новый):** для всех skills-тул-имён, попадающих в
  `tools_spec`, ни одно не является префиксом другого. Страховка от повторения
  класса бага.
- `tests/test_skills_tool_agnostic.py`, `tests/test_skills_tools_packs.py` —
  ожидания на новые канон-имена (`skills_read_reference` / `skills_read_asset`).
- `tests/skills/test_skill_delivery.py` — текст доставки содержит новые имена.

## Вне scope

- **Алиасы старых имён** — намеренно не делаем (см. «Обратная совместимость»);
  переименование чище без нового концепта в инфраструктуре.
- **Анти-коуч ошибки реестра** (`load_reference`) — безопасная generic-приписка, но
  не нужна для корня (коллизия — первичный драйвер). Добавить отдельно, только если
  на живом прогоне после переименования модель всё ещё залипает в reference-рамке.
- **Предохранитель повторов в главном цикле** — отдельная вторая линия для совсем
  слабых моделей, не корень.
- `skills_load` / `skills_list` / `skills_run_script` — не трогаем.
