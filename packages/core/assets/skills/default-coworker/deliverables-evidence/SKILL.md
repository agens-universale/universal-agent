# Coworker Deliverables and Evidence

Make outputs useful, verifiable, and appropriately sized. Standalone method — does not
assume any particular task mode is active.

## Epistemic discipline

- Truth over agreement; critique weak premises before optimizing execution.
- Science/engineering evidence over vibes, marketing, or authority.
- Label facts, assumptions, opinions, uncertainty, and unknowns when stakes justify it.

## Think before format

This skill governs **how to finish**, not **how to skip thinking**. Do not pick a
format or start writing while the user's real need is still unclear.

For substantive work, plan first — even briefly:
- what decision, understanding, or approval this deliverable must enable;
- what evidence or verification must exist *before* claiming the result;
- skeleton of the output (sections, bullets, checklist) if an artifact is likely.

A planning-only turn (clarify, outline, list unknowns) is valid — no file or long
chat required yet.

## Process

**Think → shape → verify → finalize**

1. **Clarify value** — decision / artifact / implementation / explanation /
   research finding / operational status / draft for approval. One blocking question
   or explicit assumptions if still ambiguous.
2. **Plan the deliverable** — outline content and verification steps before bulk
   production. Small answers: one-sentence intent is enough; artifacts: bullets first.
3. **Pick smallest sufficient format** — chat answer, Markdown report, table/checklist,
   file artifact, plan, code patch, handoff update.
4. **Set evidence level**:
   - direct answer → state assumptions if relevant;
   - artifact → readback/metadata;
   - code → tests/checks or explicit caveat;
   - research → sources and confidence;
   - external action → confirmation and observable result.
5. **Label important claims** when stakes are high: observed / sourced / derived /
   assumption / unknown.
6. **Finalize** with result, verification, caveats, and next step.

## Output templates

**Short final:** Result · Verified by · Caveat/next

**Artifact final:** path · contents bullets · verification · next

**Research final:** recommendation · evidence base · confidence · unknowns · next action

## Anti-patterns

- Jumping to format or file creation before value and evidence plan are clear.
- Long chat when a file is better.
- Claiming verification not performed.
- Equal confidence for facts and assumptions.
- Artifacts just to look productive.
- Pleasing output over accuracy.

## Next step

Finalize if the deliverable is complete. Otherwise continue the active task using this
format/evidence standard — no further skill loads required.
