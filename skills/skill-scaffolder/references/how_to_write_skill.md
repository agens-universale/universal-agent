# Как писать skills

Этот документ относится к демо-скиллу `skill-scaffolder` и объясняет, как оформлять новые skills.

## Обязательная структура

Каждый skill — это подпапка в `skills_data` со структурой:

```text
my-skill/
├── SKILL.md          # инструкции + метаданные (обязательно)
├── scripts/          # опционально: исполняемый код
├── references/       # опционально: документация
└── assets/           # опционально: шаблоны и ресурсы
```

## SKILL.md

`SKILL.md` должен начинаться с YAML‑фронтматтера и основного тела инструкции:

```markdown
---
id: "my-skill"
name: "My skill"
description: "Краткое описание, когда и зачем использовать."
version: "0.1.0"
---

# Инструкции для my-skill

Опиши:
- назначение скилла;
- какие действия агент может выполнять с его помощью;
- какие ограничения и предположения есть.
```

### Поля фронтматтера

- `id` — уникальный идентификатор скилла. Если не задан, берётся из имени папки.
- `name` — человекочитаемое имя (может совпадать с id).
- `description` — краткое описание, которое будет видно в `skills_list`.
- `version` — произвольная строка с версией (опционально).

## scripts/

Папка `scripts/` используется, если skill имеет исполняемую часть (например, Python‑скрипты).

Рекомендуется:

- основной вход — `scripts/main.py`;
- скрипт читает JSON из `stdin` и пишет результат в `stdout`;
- для сложных кейсов документировать ожидаемый формат `args` в `SKILL.md`.

## references/

В `references/` можно складывать:

- гайды и пошаговые инструкции;
- шпаргалки по домену;
- примеры использования.

Файлы доступны через инструмент `skills_load_reference` по slug, который соответствует пути внутри `references/` без расширения.

## assets/

`assets/` — для всего, что можно считать шаблоном или текстовым ресурсом:

- промпт‑шаблоны;
- шаблоны писем/отчётов;
- куски текста, которые часто переиспользуются.

Файлы доступны через инструмент `skills_load_asset` по тем же правилам slug, что и для `references/`.
